# 00 术语表

本表是项目内的共同语言。来源标注：`原` = 原始构想；`主` = 主控补充；`A/B` = 对应推演者提出。

| 术语 | 定义 | 来源 |
| --- | --- | --- |
| 工程控制工作流 | 把目标、任务、执行、验收、沉淀、技能、记忆组织成闭环的控制结构 | 原 |
| 目标契约 | 目的、成功判据、非目标、边界与约束、授权、验收方式、时间盒、失败预案的合称；验收的上位依据 | 主 |
| 成功判据 | 可观察、可证伪的完成条件；不是形容词 | 主 |
| 非目标 | 明确不做什么，用于防止范围蔓延 | 主 |
| 任务卡 | 自包含的执行单元，含输入、输出契约、验收标准、依赖、约束、预算、状态 | 原/主 |
| 上下文包 | 任务卡 + 记忆切片 + 约束 + 已知坑 + 判例；指针优先于拷贝 | 主 |
| 验收单 | 逐条对照验收标准的判定记录，含证据、判定、理由、偏差 | 原/主 |
| 逐条验收 | 每条标准单独判定，不做整体印象打分 | 原 |
| 独立验收 | 验收者不与被验收者共享同一上下文盲区 | 主 |
| 红队 | 专门寻找"判据未覆盖却会出问题"的对抗性评审 | B |
| 收敛 | 目标契约逐条闭环 + 遗留风险显式接受 + 记忆写回；验收通过不等于收敛 | 主 |
| 收敛门 | 宣布"完成"前的最终门禁 | 主 |
| 门禁 | 阶段转移的合法性条件 + 一个有拒绝权的角色 | 主/B |
| 目标门 / 方案门 / 验收门 / 晋升门 | 四个关键门禁，分别守住目标、方案、验收、记忆晋升 | 主 |
| UNDECIDABLE | 证据不足、无法判定的验收状态；禁止"不确定按通过处理" | B |
| 证据 / 证迹 | 第三方不追问执行者也能观察、可复现的完成依据 | B |
| 因果贴近度 | 判据与目标之间的因果距离；精确但因果遥远的判据最危险 | B |
| 责任租约 | 每个状态绑定"负责下一次转移的角色 + 期限"，超期视为失联可接手 | B |
| 基线钉定 | 任务钉住其验收所依据的判据/输入版本，版本变更触发 STALE | B |
| 伪解耦 | 看似解耦、实际仍靠对话或共享上下文维系的状态 | 主/B |
| 错误条目 | 现象、根因、影响面、修复、教训、适用范围、置信度的记录 | 原/主 |
| 教训 | 带适用条件与反例的可复用判断 | 主 |
| 归因分层 | 区分目标/判据/执行/环境四层缺陷，修复方程不同 | B |
| 技能卡 | 触发、输入、步骤、检查点、失败模式、度量、版本、失效条件的程序性知识 | 原/主 |
| 技能化 | 把高频稳定动作固化为技能卡的过程 | 原 |
| 记忆分级 | L0 元知识 / L1 项目记忆 / L2 区域记忆 | 原 |
| 晋升 | 低层记忆经证据门槛进入更高层，是提纯不是复制 | 主 |
| 退役 | 过时/被证伪/失效的记忆或技能归档，保留原因与替代者 | 主 |
| 区域记忆 | 开发、验收、收敛、协作等局部知识 | 原 |
| 接手包 | 新 agent 接手所需的最小信息结构：状态、意图、证据、未决、教训、决策、技能索引 | 主/B |
| 双环 | 执行环（G→P→D→A→C）+ 进化环（E→S→M） | 主 |
| 反模式 | 看似合理、实际导致系统退化的做法 | 主 |
| 流程重量 | 流程开销与任务风险的匹配程度 | 主 |
| 解释负债 | 读者为正确使用工件而必须重建的推理量；负债不为零处即伪解耦 | A′ |
| 陌生读者测试 | 无对话历史的 agent 只凭工件做下一步决策；做不到即未解耦 | A′ |
| 否决记录 | 哪些路已被排除、为什么；新 agent 可续行的关键信息 | A′ |
| 删除测试 | 删掉某类信息后接手者下一步是否改变；改变则不可删 | A′ |
| 回退半径 | r1 任务 / r2 方案 / r3 目标 / r4 跨工程；失败回退到哪一层的显式定义 | A′ |
| 部分通过（PARTIAL） | k/n 条判据通过；完成度是判据集的属性，不是任务的属性 | A′ |
| 漂移（DRIFT） | 执行中发现目标/判据不成立时的合法上报出口 | A′ |
| 证据封存 | 提交后证据只可追加、不可改写，防止验收对象变形 | A′ |
| 判据分层 | 稳定层（价值/约束/非目标）+ 演化层（本轮断言，可重写但留痕） | B |
| 三回路 | 验收（纠错）/恢复（续行）/进化（学习），时间尺度不同 | A′ |
| 候选区 | 未达样本门槛的技能/规则暂存区，不具正式权威 | A′/主 |
| 激励相容 | 偏差申报有正收益、隐瞒有代价，否则账本必然有偏 | A′ |
| 单模型上限 | 同模型验收发现不了共享错误前提；流程抬高一致性而非正确性 | A′ |
| 动作可逆性 | 删除/发布/批量改写等不可逆动作需更严门禁与人类确认 | A′ |
| 收敛门 | 宣布"完成"前的最终门禁：目标闭环 + 遗留显式接受 + 记忆写回 | 主 |
| 合规验收 | 逐条对照契约的验收；验"是否符合约定"，不验"是否值得要" | A(k3) |
| 价值验收 | 由目标所有者或人类确认"适合目的"；不能由执行方自证 | A(k3) |
| 工作区一致性 | 产物的可见性（草稿/候选/已验收）、可变性（唯一写者/提交封存）、失效规则（STALE/INVALIDATED） | A(k3) |
| 目标幻觉共识 | 目标讨论因迎合偏差过早收敛，全链高效执行错误目标 | A(k3) |
| 假规则沉淀 | 归因浅薄且无复核，错误归因被写成预防规则，污染后续周期 | A(k3) |
| 双账漂移 | 同一事实同时以技能和记忆两种形式维护，只更新一处导致指引矛盾 | A(k3) |
| 严格度刻度 | 按风险分档配置流程重量（轻/标准/严格）；门禁可裁剪但不可静默 | A(k3)/主 |
| 洋葱接手模型 | 接手信息按锚点/态势/行动/教训/溯源五层组织，内核最小、指针扩展 | A(k3) |
| 先归因后路由 | 失败先判病因（目标/计划/执行/验收），再决定回退到哪一层 | A(k3) |
| 进化自质量门 | 归因→规则晋升须独立复核；设"归因不明→观察"；L0 需人类批准 | A(k3) |
| 责任稀释 | 多 agent 链式交接后无人对最终结果负责 | 主 |
| 高质量假象 | 所有门禁通过、交付物却不可用的状态；由目标不可判定与验收同源共同制造 | 主 |
