# 05 漏洞、缺陷与不足

本文件是对原构想最不客气的部分。分四类：**概念漏洞**（缺了什么）、**失效模式**（什么条件下会坏）、**结构性张力**（无法消除、只能平衡的矛盾）、**反模式与边界**（什么情况下不该用）。

## 1. 概念漏洞

原构想覆盖了主干，但以下概念缺位。缺位不等于错误，但会导致流程在真实压力下退化。

| 编号 | 缺口 | 为什么致命 | 建议补充 |
| --- | --- | --- | --- |
| G1 | 没有显式的收敛判定 | 逐条验收通过 ≠ 目标达成；"任务都关了"会被误当完成 | 收敛门：目标闭环 + 遗留显式接受 + 记忆写回 |
| G2 | 没有目标变更管理 | 执行中目标漂移是常态；无变更控制则验收依据失效 | 目标版本、变更申请、影响分析、重新验收范围 |
| G3 | 没有冲突仲裁 | 多 agent 结论冲突、验收争议、记忆冲突时无人裁决 | 仲裁者角色 + 裁决记录 + 升级路径 |
| G4 | 没有生命周期与退役 | 记忆只增不减、技能只立不废，系统必然腐化 | 复审日期、失效条件、归档而非删除 |
| G5 | 没有人类门禁与责任主体 | 全自动闭环在关键判断上无人负责 | 三处人类门禁：目标确认、争议终裁、元知识晋升 |
| G6 | 没有度量 | 无法证明"进化"真实发生，容易自我叙事 | 复发率、返工率、接手时间、争议率等 |
| G7 | 没有定义验收独立性 | 自验自过是最常见的质量幻觉 | 验收者与执行者上下文隔离；高风险任务引入红队 |
| G8 | 没有记忆写入/晋升/淘汰规则 | 分级只是三个文件夹，最终变成垃圾场 | 证据门槛、适用范围、反例、复审、所有者 |
| G9 | 没有成本模型 | 治理开销可能超过收益，流程变成负担 | 按风险分级裁剪：轻任务轻流程 |
| G10 | 没有权限与安全边界 | 记忆越权、验收越权、目标被越权修改 | 分级授权；敏感信息不进高层记忆 |

## 2. 失效模式

严重度：高 = 会导致交付失败或系统性错误；中 = 显著降低质量或效率；低 = 局部摩擦。

| 编号 | 失效模式 | 触发条件 | 后果 | 严重度 | 早期信号 |
| --- | --- | --- | --- | --- | --- |
| F01 | 目标不可判定 | 成功判据是形容词而非可观察状态 | 验收争议、无限返工、目标被解释权绑架 | 高 | 验收会上反复争论"算不算完成" |
| F02 | 目标漂移 | 执行中发现更好的方向，未经变更控制就改 | 做完发现不是最初要的；验收依据失效 | 高 | 任务卡与目标契约对不上 |
| F03 | 伪解耦 | 关键约定只在对话里；状态不落盘 | 中断即失忆；换 agent 即重来 | 高 | 新 agent 问"之前怎么定的" |
| F04 | 验收同源 | 执行者自己验收，或验收者共享同一上下文 | 盲区共振，缺陷被系统性放过 | 高 | 验收单全是"通过"，无偏差记录 |
| F05 | 局部最优 | 任务分解与目标脱钩，每项都过但整体偏 | 交付物"合格但没用" | 高 | 目标判据无人逐条对照 |
| F06 | 验收标准漂移 | 执行中悄悄放宽标准以"推进度" | 质量底线逐轮下移 | 高 | 验收标准版本与任务卡不一致 |
| F07 | 指标游戏 | 验收标准可被低成本满足 | 为通过而做，不为目标而做 | 中高 | 指标好看但用户/目标无感 |
| F08 | 错误过度泛化 | 一次错误就写成通用规则 | 教条束缚正确做法；规则互相冲突 | 中高 | 规则数量快速增长，例外越来越多 |
| F09 | 错误集收偏差 | 只收被发现的错误，漏掉沉默失败 | 幸存者偏差；真实缺陷率被低估 | 高 | 台账很干净，但返工不断 |
| F10 | 技能腐化 | 环境变化但技能未复审 | 按过时步骤执行，错得"很规范" | 中高 | 技能失败率上升，仍被调用 |
| F11 | 技能库膨胀 | 什么都技能化，缺乏退役 | 检索困难、误用、维护成本失控 | 中 | 同类技能多个版本并存 |
| F12 | 记忆污染 | 无来源/低置信度条目被晋升 | 错误知识被后来者继承 | 高 | 记忆条目无法回溯来源 |
| F13 | 记忆冲突 | 同一问题存在两条相反记忆 | 执行者各取所需，行为不一致 | 中高 | 两个 agent 对同一规则理解相反 |
| F14 | 反馈震荡 | 每次错误都改流程，缺乏节流与回滚 | 系统不稳定，规则频繁失效 | 中 | 流程版本周周变，执行者无所适从 |
| F15 | 责任稀释 | 多 agent 链式交接，无明确 owner | 出问题找不到责任人；无人对最终结果负责 | 高 | "这是上一个环节的问题" |
| F16 | 恢复不一致 | 半成品未标记，恢复者当完成品继续 | 缺陷被下游放大 | 高 | 下游基于未验收产物开工 |
| F17 | 度量作弊 | 指标可被选择性报告 | 进化叙事与真实能力脱节 | 中 | 指标改善但事故率不降 |
| F18 | 成本失控 | 验收/记忆/技能治理过重 | 流程开销 > 收益，团队绕过流程 | 中高 | 大家开始"先做后补" |
| F19 | 安全越权 | 记忆或验收权限未分级 | 敏感信息泄露；越权验收 | 高 | 任何 agent 都能改任何记忆 |
| F20 | 人类缺位 | 关键判断全交给 agent | 责任无法落地；价值判断失真 | 高 | 重大决策无人类签字 |
| F21 | 组合性盲区 | 任务分解过细，且没有集成断言 | 每条都通过、整体不工作；缺陷落在任务缝隙无人负责 | 高 | 集成/整体演示缺席，或没人负责 |
| F22 | 判据后置/判据漂移 | 验收阶段才写判据，或判据向"容易通过"漂移 | 验收退化为事后合理化，逐条验收变成逐条辩护 | 高 | 判据在派发后才出现或版本对不上 |
| F23 | 约束与成本缺位 | 没有预算、禁区、止损线 | 系统只能因"做错"失败，不能因"太贵"失败 | 中高 | 范围无限追加，无人有权叫停 |
| F24 | 无删除权 | 记忆与技能只增不减，无人有权退役 | 新 agent 读到互相冲突的指令，规则体系失去权威 | 中高 | 同类规则多版本并存，无人清理 |
| F25 | 目标通胀（过度回退） | 判据模糊 + 验收严格，每次失败都回 r3 重谈目标 | 永不收敛，预算爆炸 | 高 | 目标版本频繁变更，里程碑反复重置 |
| F26 | 验收二值化 | 状态机只有全过/全不过，没有部分通过 | 逐条验收退化为"整体印象加长版"；执行者硬做或隐瞒 | 高 | 任务只有"完成/未完成"，没有 k/n |
| F27 | 偏差申报激励不相容 | 自报偏差无收益、隐瞒无代价 | 账本只剩被抓到的错误，生存者偏差，进化是假的 | 高 | 台账很干净，返工却不断 |
| F28 | 不可逆越权 | 动作可逆性未分级，删除/发布与可回滚修改同一门禁 | 低频高损，无法从事后证据恢复 | 高 | 一次误操作造成不可逆影响 |
| F29 | 判据作者不独立 | 规划者既写判据，又拿验收反馈调优判据 | 判据向"容易通过"漂移，验收即自证 | 高 | 判据越改越松，通过率越来越高 |
| F30 | 技能早熟 | 样本 1–2 即固化，高频动作定义过宽 | 错误被制度化，比单次错误更贵 | 高 | 技能库快速膨胀，失败率同步上升 |
| F31 | 门禁空转 | 门禁判据不可观测（"已确认""已阅读"） | 流程成本上升，缺陷率不变 | 中 | 门禁全绿但事故照旧 |
| F32 | 验收死循环 | 判据按理想态而非可观测态书写 | 永久退回，或被迫降低标准（退回 F06） | 中 | 同一判据反复"差一点" |
| F33 | 目标幻觉共识 | 目标讨论因迎合偏差过早收敛 | 全链高效执行错误目标 | 高 | 讨论很快一致，无人提出反例 |
| F34 | 价值验收缺失 | 只验契约合规，无人确认"适合目的" | 交付了没人要的东西 | 中高 | 验收全绿但用户不用 |
| F35 | 半成品污染 | 产物无可见性状态，被其他任务读取 | 错误跨任务传播，返工 | 中高 | 下游引用了未验收产物 |
| F36 | 双账漂移 | 同一事实技能与记忆两处存，只更新一处 | 指引自相矛盾，行为不确定 | 中 | 同一规则两处说法不同 |
| F37 | 变更雪崩 | 目标变更未使在途契约失效 | 验收了已过时的交付物 | 中高 | 目标已改，任务照旧执行 |
| F38 | 粒度错配 | 任务超出执行者可靠上下文包络 | 静默丢失需求，验收只能捞回一部分 | 中高 | 执行者遗漏关键约束却"完成了" |

## 3. 结构性张力

这些不是"修好就不存在"的缺陷，而是**必须长期平衡的矛盾**。工作流设计的好坏，取决于是否为这些张力留了调节旋钮。

| 张力 | 失衡表现 | 平衡原则 |
| --- | --- | --- |
| 解耦 ↔ 上下文完整性 | 解耦越彻底，上下文越碎；执行者反复问"背景是什么" | 工件契约 + 指针；按任务需要切片，不追求全局同步 |
| 验收严格 ↔ 交付速度 | 验收越细越慢；团队开始绕过验收 | 按风险分级验收：高风险全检，低风险抽检 |
| 记忆丰富 ↔ 检索噪声 | 记得越多，命中越难 | 分层 + 切片 + 复审；L0 少而硬 |
| 技能固化 ↔ 环境适应 | 技能越固化，越难应对新情况 | 技能带失效条件与复审；保留"不用技能"的例外通道 |
| 自动化 ↔ 责任归属 | 越自动，越难说清谁负责 | 明确 owner；关键节点人类签字 |
| 标准化 ↔ 探索性 | 流程越标准，越不适合探索 | 双模式：执行型走标准流程，探索型走轻流程 |
| 独立验收 ↔ 上下文成本 | 独立验收要重建上下文，成本高 | 验收者读工件而非对话；高风险才要求完全独立 |
| 逐条严格 ↔ 全局完整 | 每条都过，整体不工作 | 增加集成断言与红队；承认"局部严格"是交换，不是免费 |

## 4. 反模式

- **流程表演**：为了"有流程"而走流程，门禁签字但不看内容。
- **验收形式化**：验收单全绿，偏差栏永远为空。
- **记忆囤积**：什么都记，从不复审，检索全靠运气。
- **技能崇拜**：把技能数量当成熟度，忽视失效与维护。
- **指标驱动**：为了让指标好看而工作，而不是为了目标。
- **全自动幻想**：把需要价值判断的决策交给 agent，出问题再找人背锅。
- **文档替代思考**：工件齐全，但没人真的想过目标是否成立。
- **过度契约**：每个微小动作都要工件，协调成本压垮执行。

## 5. 边界：什么情况下不该用这套工作流

- **目标本身不可判定**（研究、创意、战略探索）：应改用探索型流程，验收对象是"问题定义与选项质量"，不是交付物。
- **强实时场景**：门禁与验收的延迟不可接受。
- **强安全/强合规责任场景**：必须人类主导，agent 只能辅助。
- **极小任务**：流程开销大于任务本身。
- **一次性、高度特化项目**：记忆与技能的复用收益趋近于零。
- **团队规模极小且任务同质**：口头协作可能比工件协作更高效；但一旦需要接手或审计，仍应补最小工件。

## 6. 最危险的三个漏洞（排序）

如果只能先修三个，建议是：

1. **目标不可判定（F01）+ 验收同源（F04）**：这两者叠加会制造"高质量假象"——所有门都过了，交付物却不能用。
2. **伪解耦（F03）+ 恢复不一致（F16）**：长任务必然中断，中断即失忆会让前面所有工作归零。
3. **错误过度泛化（F08）+ 记忆污染（F12）**：进化机制本身会变成污染源，越"进化"越僵化。

这三组漏洞的共同点：**它们不会立刻报错，而是让系统在"看起来正常"的状态下慢慢失效**。这也是为什么需要度量与独立验收——它们是唯一能提前暴露这类慢性失效的传感器。

同等级但更隐蔽的一组是 **F21（组合性盲区）+ F22（判据后置/漂移）**：逐条验收用局部严格交换了全局完整，而判据后置让这场交换看起来成功。它的信号不是"失败"，而是"全部通过却没人能用"。
