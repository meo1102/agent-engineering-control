# 04 记忆分级与进化：从错误到技能，从区域到元知识

## 1. 为什么必须分级

三个事实决定了记忆不能只做一层：

- **上下文有限，知识无限**：不可能每次把全部经验塞进上下文；
- **知识的寿命与适用范围不同**：有的原则跨项目成立，有的只在本项目成立，有的只在本周成立；
- **证据要求不同**：越通用的知识，错了影响面越大，越需要高证据门槛。

不分级的记忆最终会变成垃圾场：检索不到、互相冲突、局部经验污染全局判断。分级的目的不是"分三个文件夹"，而是让不同寿命、不同范围、不同证据强度的知识**各得其所，并且可治理**。

分级的三个维度：**适用范围**（跨项目 / 项目 / 区域）、**变化频率**（慢 / 中 / 快）、**证据要求**（高 / 中 / 低）。

## 2. 三层结构

### L0 元知识（跨项目）

- **内容**：原则、模式、反模式、判断准则、决策启发式。
- **特征**：跨项目成立、变化慢、数量少、证据门槛最高。
- **示例（概念级）**："验收标准必须在任务开始前写定"；"样本为 1 的错误只能成为观察，不能成为规则"；"高风险任务需要独立验收"。
- **写入条件**：跨 ≥2 个项目复现 + 反例检验 + 人类批准 + 复审日期。
- **风险**：一旦被污染，影响面最大；所以晋升最难、退役最慎重。

### L1 项目记忆（本项目全局）

- **内容**：目标契约、关键决策与理由、术语表、约束、里程碑、风险台账、错误台账索引、验收判例、收敛记录。
- **特征**：项目生命周期内有效，中频更新。
- **写入触发**：目标契约定稿、方案定稿、重大决策、验收争议裁决、收敛完成。
- **主要消费者**：新 agent 接手、任务派发、验收争议、复盘。

### L2 区域记忆（局部）

按工程区域划分，典型四区：

| 区域 | 记什么 | 典型条目 |
| --- | --- | --- |
| 开发记忆 | 实现约定、代码地图、环境坑、常见缺陷 | "某类改动必须先跑冒烟" |
| 验收记忆 | 判例、边界案例、常见误判 | "这类输出要看边界值而不是平均值" |
| 收敛记忆 | 收敛判据、遗留问题模式、发布记录 | "哪些遗留可以接受、哪些必须清零" |
| 协作记忆 | 派发经验、上下文包模板、执行者画像 | "哪类任务适合哪种执行者" |

- **特征**：高频、局部、易变。
- **写入触发**：任务执行、验收、派发、复盘即时写。

## 3. 记忆条目规范

每条记忆必须能回答：**从哪来、有多可信、在什么范围内成立、什么情况下不成立、什么时候复审、谁负责。**

字段：ID、层级、区域、标题、内容、来源、时间、置信度、适用范围、反例、复审日期、所有者、状态（active / superseded / archived）。

**三类内容必须区分**，混在一起会导致"事实被判断污染"：

- **事实**：发生了什么（可验证）；
- **判断**：我们怎么理解（可争议）；
- **决策**：我们选了什么、为什么（可追溯）。

## 4. 写入、读取、晋升、淘汰

**写入**：由事件触发，而不是"想起来就写"。触发点：目标契约定稿、方案定稿、验收完成、收敛、错误归因、技能发布、重大决策。

**读取**：按任务上下文检索，**切片注入**，不整层加载。读什么由任务卡与风险决定，不由"尽量多给"决定。

**分层召回**：L2 观察层可以广收（写入成本低、局部、可失效）；L1/L0 规则层必须严进（证据门槛、反例、批准）。原因是：记忆写入成本低、读取成本高、错误记忆的传播成本极高——高层记忆应优化精确率，而不是召回率。宁可漏记一条经验，不可错记一条规则。

**晋升**：

- L2 → L1：跨任务复现（≥N 次）、适用条件稳定、项目所有者批准；
- L1 → L0：跨项目复现（≥2 个项目）、通过反例检验、人类批准。

晋升是**提纯**，不是复制：晋升后的条目要去掉项目特化细节，保留可迁移的判断与适用条件。

**降级 / 淘汰**：

- 失效：适用范围消失（技术换代、约束解除）；
- 被证伪：新证据推翻旧结论；
- 被替代：有更新的条目覆盖；
- 长期未复审：超过复审日期自动降级为"待验证"。

淘汰不是删除，是归档并保留原因与替代者，保证审计链不断。

**冲突解决**：新证据优先；旧条目保留并标记 superseded；无法裁决时升级到仲裁或人类，裁决本身写入决策记录。

## 5. 错误 → 教训 → 技能 → 记忆 的进化链

```
错误条目（现象）
   │ 归因、去重、区分点错误/模式错误
   ▼
教训（判断 + 适用范围 + 反例）
   │ 抽象为约束或程序
   ▼
规则/检查项（进入方案检查表、验收标准）      技能卡（进入执行）
   │                                          │
   └──────────────→ 记忆写回 ←────────────────┘
              L2 区域 → L1 项目 → L0 元知识
```

**晋升阶梯（证据门槛）**：

| 证据强度 | 可以成为什么 | 不能成为什么 |
| --- | --- | --- |
| 1 次错误 | 区域观察记录 | 项目规则、元知识 |
| 同根因 ≥2 次 | 项目级教训 / 检查项 | 元知识 |
| 跨 ≥2 项目复现 | 元知识候选 | （需人类批准才正式生效） |
| 步骤稳定 + 有检查点 | 技能卡 | （不能替代判断类知识） |
| 技能反复调用且有效 | 保留并复审 | （不自动升级为原则） |

**核心原则**：**样本为 1 的错误只能成为"观察"，不能成为"规则"。** 过度泛化是记忆系统最常见的自伤方式——一次偶然失误被写成铁律，反而束缚了未来的正确做法。

**单一出处**：同一事实不同时以"技能"和"记忆"两种形式维护。技能是程序性知识（如何做），记忆是陈述性知识（知道什么）；同一内容两处存放，只更新一处就会产生"双账漂移"，让后来者无所适从。

**候选区**：步骤稳定但样本不足的动作/规则，进入候选区而不是正式库；候选条目必须带样本量、失效条件与复审日期，达到门槛后才转正。候选区是"早沉淀"与"防污染"之间的折中：既保留复用机会，又不让未经验证的经验获得制度权威。

## 6. 记忆的治理

- **所有者**：每层设记忆管理员（Librarian）；L0 的变更需人类批准。
- **复审周期**：L2 短（随任务）、L1 中（随里程碑）、L0 长（按季度/半年）。
- **记忆预算**：L0 条目数应受控（概念上"少而硬"），否则检索退化为噪声；L1 按项目规模控制；L2 按区域控制。
- **访问分级**：记忆分级同时意味着权限分级；敏感信息不进入高层记忆。
- **遗忘机制**：归档而非删除；保留"为什么被遗忘"。
- **度量**：命中率、复用率、冲突率、过期率、错误复发率、变更回滚率。

## 7. 新 agent 如何用记忆

- **接手时**：L1 摘要 + 当前状态 + 未决问题 + Top 教训；
- **执行时**：L2 区域切片 + 技能索引；
- **决策时**：L0 原则 + L1 决策记录 + 验收判例；
- **反馈时**：执行中发现的新坑先写 L2，不直接改 L0；
- **禁止**：把"记忆里没写"当作"不需要做"，把"记忆里写了"当作"一定对"。

## 8. 进化的度量

没有度量，"进化"只是叙事。可用的概念级指标：

| 指标 | 说明 | 期望方向 |
| --- | --- | --- |
| 错误复发率 | 同一根因再次出现的比例 | 下降 |
| 返工率 | 被退回任务占全部任务的比例 | 下降 |
| 验收争议率 | 需要仲裁的验收比例 | 下降 |
| 接手时间 | 新 agent 从接手到可独立产出的时间 | 下降 |
| 技能复用率 | 技能被调用的次数/任务数 | 上升后趋稳 |
| 记忆命中率 | 检索到的记忆被实际采用的比例 | 上升 |
| 记忆过期率 | 超过复审日期未处理的条目比例 | 下降 |
| 变更回滚率 | 流程/规则变更后被回滚的比例 | 稳定在低水平 |

## 9. 反模式

- **记忆即日志**：什么都记，等于什么都没记；
- **元知识通胀**：什么都往 L0 放，L0 失去权威性；
- **只写不读**：记忆成为负担而不是资产；
- **只增不删**：系统腐化，检索失真；
- **无来源记忆**：无法验证，无法追责；
- **记忆与工件重复**：两份真相，必然冲突；
- **技能与记忆混淆**：把"知道"当"会做"，把"会做"当"知道"。

## 10. 小结

分级不是目的，**可治理**才是。晋升、复审、退役三个动作，是记忆系统从"文件夹"变成"活体"的关键；没有这三个动作，三层结构只是三个越来越大的垃圾桶。
