# 06 优势、代价与适用边界

## 1. 优异点

### 1.1 把隐性经验变成显性资产

传统 agent 协作中，关键约定、踩过的坑、判断依据都留在对话里；换个会话或换个 agent 就消失。本工作流要求目标、决策、判例、坑都落到工作区，经验从"个人记忆"变成"项目资产"。

**成立条件**：写回是强制的，且有人复审；否则只是把聊天记录换了个地方存放。
**不成立条件**：工件写了但没人读；记忆没有晋升与淘汰，最终被噪声淹没。

### 1.2 解耦带来的可替换、可并行、可审计

阶段之间只通过工件契约交互，因此：执行者可以替换、任务可以并行、过程可以审计、中断可以恢复。这是"工程"与"手工作坊"的分水岭。

**成立条件**：工件契约完整、状态持续维护、验收独立。
**不成立条件**：伪解耦——关键信息仍在对话里，换人即失效。

### 1.3 验收标准前置，缺陷早发现

验收标准在派发前写定，执行者知道"什么算完成"，验收者知道"按什么判"。缺陷从"交付后发现"前移到"派发时预防"。

**成立条件**：验收标准可判定、且不在执行中被悄悄放宽。
**不成立条件**：标准是形容词；或为了推进度而事后修改标准。

### 1.4 错误沉淀形成组织学习飞轮

错误 → 教训 → 规则/检查项/技能 → 记忆 → 下一次目标与派发。每一次失败都让系统变强一点，而不是重复付费。

**成立条件**：归因到根因、区分点错误与模式错误、有证据门槛。
**不成立条件**：样本为 1 就晋升为规则；或错误只处理不沉淀。

### 1.5 技能化降低重复推理成本与方差

高频元动作（目标澄清、任务拆解、验收、归因、记忆写入）固化为技能后，执行更快、更一致、更少遗漏。对 agent 而言，技能化还显著降低了"每次都要重新想一遍"的上下文消耗。

**成立条件**：动作高频、稳定、有检查点；技能有失效条件与复审。
**不成立条件**：技能腐化仍被调用；技能库膨胀导致检索与误用。

### 1.6 分级记忆缓解上下文约束

L0/L1/L2 让"跨项目原则、项目全局、区域细节"各归其位，按任务切片注入，既避免上下文爆炸，又保证关键约束不丢。

**成立条件**：分层清晰、晋升有门槛、检索按上下文。
**不成立条件**：元知识通胀；记忆冲突；只写不读。

### 1.7 工作区作为协作总线，天然支持中断恢复与异步

任务指派与成果验收都通过工作区协作，不依赖实时对话；中断后从工作区恢复；新 agent 靠接手包进入状态。这使长周期、多 agent、跨会话的工程成为可能。

**成立条件**：状态与意图都落盘；半成品有标记；接手包完整。
**不成立条件**：工作区只有结果没有理由；状态文件长期不更新。

### 1.8 可度量

相对"感觉良好"，这套结构天然产生可度量信号：验收通过率、返工率、错误复发率、接手时间、争议率。度量让"进化"从叙事变成可检验的假设。

**成立条件**：指标定义稳定、数据不被选择性报告。
**不成立条件**：指标被游戏化；只报喜不报忧。

## 2. 代价

任何控制结构都有成本，不承认成本的设计必然被绕过。

| 代价 | 具体表现 | 控制方式 |
| --- | --- | --- |
| 前期开销 | 目标讨论、任务卡、验收单都要时间 | 按风险分级：轻任务轻流程 |
| 协调成本 | 工件维护、版本管理、状态同步 | 工件契约精简；指针优先；自动化能省则省 |
| 认知负担 | 规则、记忆、技能需要学习与记忆 | 技能化元动作；L0 少而硬；模板化 |
| 僵化风险 | 流程压过判断，探索被抑制 | 双模式：执行型/探索型；允许例外但留痕 |
| 人的时间 | 人类门禁需要真正参与 | 门禁设在关键处，不做形式签字 |
| 环境依赖 | 依赖工作区作为协作总线 | 工作区可迁移、可离线、可审计 |

**成本原则**：治理开销应与任务风险成比例。用同一套重流程处理所有任务，是最常见的失败原因之一。

## 3. 与替代方案的比较

| 方案 | 可控性 | 可恢复性 | 可积累性 | 开销 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 临时协作（ad-hoc） | 低 | 低 | 低 | 最低 | 一次性小任务 |
| 传统瀑布 | 高 | 中 | 中 | 高 | 需求稳定、合规要求高 |
| 敏捷/看板 | 中高 | 中 | 中 | 中 | 需求变化快、团队协作 |
| 多 agent 框架 | 取决于框架 | 取决于框架 | 低（多数只解决连接） | 中 | 任务并行、工具编排 |
| 知识管理 | 低（对交付） | 中 | 高 | 中 | 组织学习 |
| **本工作流** | 高 | 高 | 高 | 中高（可分级） | 多 agent、长周期、需接手与审计的工程 |

本工作流的差异点不在"连接 agent"，而在**控制、验收、积累、接手**四件事同时成立。

## 4. 适用与不适用

### 适用

- 目标可分解、可判定；
- 任务可并行或可分阶段；
- 经验有复用价值；
- 多 agent 或跨会话协作；
- 长周期、需要接手与审计；
- 质量与可追溯性优先于极致速度。

### 不适用（或需换形态）

- 目标不可判定（研究、创意、战略探索）→ 探索型流程；
- 强实时 → 门禁延迟不可接受；
- 强安全/合规责任 → 人类主导；
- 极小任务 → 开销大于收益；
- 一次性特化项目 → 复用收益趋零；
- 团队极小且同质 → 口头协作可能更高效（但接手/审计时仍需最小工件）；
- **验证成本远高于执行成本** → 逐条验收经济上不成立，应改为抽样 + 不变量；
- **反馈周期长于工程周期** → 只能验过程合规，逐条验收退化为合规表演；
- **目标本身是多方博弈** → G0 不是认知问题而是权力问题，agent 无法单独收敛；
- **模型能力跃升期** → 重流程的边际收益下降，流程可能从"赋能"变成"束缚"；
- **产出难以外化**（品味、架构直觉、探索性研究）→ 工作区留得住结果、留不住理由，恢复与验收同时退化；
- **强耦合系统**（全局一致性、架构级不变量）→ 任务级验收失效，集成故障落在契约缝隙里，需整体验收；
- **假设所有 agent 善意** → 工作区工件会成为注入面，对抗性内容在模型之外；
- **低于复杂度/风险阈值** → 仪式成本超过失败成本，流程沦为官僚主义。

### 降级方案（灰色地带）

- **轻量版**：目标契约 + 任务卡（含验收标准）+ 验收单 + 错误台账。适合中小项目。
- **探索版**：问题定义 + 选项评估 + 决策记录 + 复盘。适合目标本身在演化的场景。
- **接管版**：接手包 + 状态 + 未决问题 + Top 教训。适合中途接手，不要求补全历史。

## 5. 一句话价值主张

这套工作流不承诺"让 agent 更聪明"，它承诺的是：**让 agent 的工作可控制、可验收、可积累、可接手。**

## 6. 成功判据（概念级）

- 新 agent 接手到可独立产出的时间下降；
- 同类错误复发率下降；
- 验收争议率下降；
- 交付物与目标契约的偏差可解释、可追溯；
- 流程开销占工程总投入的比例可接受，且随风险升降。
