# 03 解耦与工作区协作：让阶段之间只通过工件对话

## 1. 解耦的三种误读

- **误读一：解耦 = 不沟通。** 实际上解耦要求更精确的沟通——把"说清楚"从对话里搬到契约里。
- **误读二：解耦 = 拆成独立 agent。** 实际上拆的是**状态与职责**，不是上下文；拆完仍然共享同一个工作区。
- **误读三：解耦 = 异步。** 异步只是解耦的结果之一，不是定义。

**本文的定义**：阶段之间不共享隐含状态，只共享**显式工件**与**显式状态**。任何一个阶段，在不读其他阶段对话历史的情况下，仅凭工作区就能被理解、执行、验收、接手。

**更硬的判据：解释负债**。把结论写进文件容易，把"它在什么前提下成立"写进文件难。A、B 两个环节真正解耦，当且仅当 B 仅凭工件即可正确使用 A 的输出，**不需要重建 A 的推理历史**。读者为正确使用工件而必须补上的推理量，就是解释负债；负债不为零处，即为伪解耦。解耦不是布尔量：目标不是把负债降到零（那会让工件膨胀到不可读），而是让负债**可控**——读者重建成本小于重新推导成本。

## 2. 伪解耦的四种形态

很多"看起来很解耦"的流程，实际上是伪解耦：

| 形态 | 表现 | 后果 |
| --- | --- | --- |
| 对话耦合 | 关键约定只存在于聊天记录里 | 会话一断，约定消失 |
| 上下文耦合 | 每个阶段都依赖同一个超长上下文窗口 | 换 agent 即失效；上下文超限即崩溃 |
| 隐性契约 | 输出格式、完成标准靠默契 | 交接失真、反复返工 |
| 时间耦合 | 必须同一会话、连续完成 | 中断不可恢复；无法并行 |

**判断方法**：换一个 agent（陌生读者）、隔一天、只读工作区，能不能继续？不能，就是伪解耦。更强的方法：让陌生读者只凭工件做出与原执行者相同的下一步决策；做不到，说明解释负债没有被清偿。

## 3. 工作区作为协议（Workspace as Protocol）

工作区不是"存放文件的地方"，而是**阶段之间的通信协议**：

- **单一事实源**：工作区是唯一可信状态；对话是传输层，不是存储层。重要结论必须回写工作区。
- **三个必备区域**：
  - 状态区：当前阶段、任务状态、阻塞点、下一步；
  - 工件区：目标契约、方案、任务卡、产物、验收单、收敛报告；
  - 知识区：错误台账、教训、技能卡、记忆条目、决策记录。
- **可预测的定位**：同一类工件放在可预测的位置，命名稳定，便于人和 agent 检索。
- **唯一写者**：每个工件有且只有一个所有者（owner）；读者不限，写者变更必须登记。
- **可见性状态**：产物标记为草稿 / 候选 / 已验收 / 已废弃；未验收产物不得被下游当作事实读取。
- **失效规则**：目标或判据变更时，旧产物与在途任务显式标记 `STALE` / `INVALIDATED`，不得静默继续。
- **版本与替代**：更新不覆盖历史；旧版本标记为 superseded，保留原因。

## 4. 工件契约

每个工件都必须回答五个问题：**谁生产、谁消费、包含什么、什么算合格、何时失效。**

| 工件 | 生产者 | 主要消费者 | 合格判据 |
| --- | --- | --- | --- |
| 目标契约 | 目标所有者 | 规划者、验收者、记忆 | 目标门五条 |
| 方案 | 规划者 | 执行者、验收者 | 方案门五条 |
| 任务卡 | 规划者 | 执行者 | 自包含、验收标准可判定 |
| 上下文包 | 派发者 | 执行者 | 指针完整、约束齐全、无过期信息 |
| 产物 | 执行者 | 验收者 | 符合输出契约、位置可定位 |
| 执行记录 | 执行者 | 验收者、沉淀者 | 偏差与未决问题完整 |
| 验收单 | 验收者 | 收敛者、记忆 | 逐条、有证据、有判定 |
| 收敛报告 | 收敛者/目标所有者 | 记忆、下一轮 | 目标闭环、遗留显式 |
| 错误条目 | 沉淀者 | 规划者、记忆 | 根因可信、教训带适用范围 |
| 技能卡 | 技能所有者 | 执行者 | 触发清楚、有检查点与失效条件 |
| 记忆条目 | 记忆管理员 | 所有阶段 | 来源、置信度、范围、复审日期 |
| 决策记录 | 决策者 | 后来者 | 背景、选项、决定、后果 |
| 接手包 | 记忆管理员/主控 | 新 agent | 状态 + 意图 + 证据 + 未决 |

**工件契约的价值**：它把"我以为你懂"变成"你可以检查我是否合格"。没有契约的工件只是文件，不是协作接口。

## 5. 上下文包：指针优先于拷贝

**为什么不要拷贝**：拷贝会过期、会膨胀、会失真；三份拷贝之后，没人知道哪份是真的。

**指针的四种类型**：

1. 工件指针：指向目标契约、方案、任务卡、判例；
2. 记忆切片指针：指向相关记忆条目（不是整层记忆）；
3. 约束指针：指向不可违反的边界与规范；
4. 证据指针：指向已有验收证据，避免重复验证。

**最小上下文包**：任务卡 + 3–5 条最相关记忆切片 + 已知坑 + 验收标准 + 回报格式。
**上下文预算原则**：给执行者的上下文是有限资源，按相关性排序，不按完整性堆砌；宁可少而准，不要多而杂。

## 6. 中断恢复

**恢复需要的三类信息**：

- **状态**：现在到哪了（阶段、任务状态、最后更新）；
- **意图**：为什么到这（目标、决策、取舍）；
- **证据**：什么已经被确认（验收单、证据指针）。

**工作区必须持续维护的"当前状态"**：当前阶段、进行中的任务、最后更新时间、阻塞点、下一步动作、等待谁。

**恢复演练**：定期让一个新 agent 只读工作区，复述"现在该做什么、为什么、怎么算完成"。复述不出来，说明工作区的可恢复性不达标。

**半成品处理**：中断时未完成的产物一律标为候选；恢复者先判断可用性，再决定复用还是重做；判断过程留痕。

## 7. 新 agent 接手

**接手包（Onboarding Pack）的八件套**：

1. 项目一页纸：目标契约摘要 + 当前阶段；
2. 当前状态与下一步；
3. 未决问题与阻塞点；
4. 最近 5 条教训与 Top 风险；
5. 关键决策记录（重点是"为什么"，不是"是什么"）；
6. **否决记录：哪些路已被排除、为什么**——这是"可续行"与"重新分叉"的分水岭；
7. 术语表与工件地图；
8. 技能索引（哪些高频动作已有技能可调用）。

**删除测试（衡量最小必要信息）**：删掉某类信息后，接手者的下一步是否必然不同？不同则不可删。用这个测试，"全量对话历史"可删，而"否决记录、假设与置信、判据↔证据对应"必留。最小 ≠ 最少，而是**充分且不可再删**。

**接手测试**：在没有任何对话上下文的情况下，新 agent 能否在有限时间内回答——现在做什么、为什么做、怎么算完成、卡在哪、找谁裁决。五项全答得出，才算真正可接手。

## 8. 协作的总线模型

- **工作区 = 总线**：所有阶段挂在同一总线上，不点对点私聊。
- **工件 = 消息**：有格式、有生产者、有消费者、有生命周期。
- **状态 = 游标**：谁读到哪、谁处理到哪，可追溯。
- **对话 = 临时通道**：用于澄清与协商；结论必须回写总线，否则视为未发生。
- **同步点 = 门禁**：需要共同确认的地方设门；其余地方异步。
- **冲突 = 双写**：两个写者改同一工件时，由 owner 裁决，版本合并留痕。

## 9. 反模式

- **工作区当垃圾桶**：什么都往里放，没有结构、没有生命周期、没有 owner。
- **对话当数据库**：关键决策只存在于聊天里，工作区只有结果没有理由。
- **过度契约**：每个微小动作都要工件，协调开销压垮收益。
- **无主工件**：谁都能改，最后谁都不负责。
- **快照腐败**：状态文件长期不更新，比没有状态文件更危险，因为它制造"可恢复"的假象。

## 10. 解耦是否成立的六个测试

1. **陌生读者测试**：没有对话历史的 agent，只凭工件能否做出与原执行者相同的下一步决策？
2. **换人测试**：新 agent 只读工作区，能否继续？
3. **隔时测试**：隔 24 小时再继续，上下文是否仍然完整？
4. **断链测试**：删掉全部对话历史，工作区是否自足？
5. **替换测试**：换一个执行者，任务卡是否仍然可用？
6. **审计测试**：能否从任一结论回溯到目标与证据？

六个测试中任意一个失败，说明解耦只是表面的，实际仍靠对话或记忆维系。**能恢复状态不等于能续行**：如果只存产物、不存否决记录与假设，接手者可能走向另一个分支——那是分叉，不是续行。
