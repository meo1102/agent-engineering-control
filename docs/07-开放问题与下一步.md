# 07 开放问题与下一步

## 1. 概念级开放问题

以下问题在概念阶段无法被彻底回答，但必须先被识别，否则会在实现阶段以"技术问题"的面目爆发。

**Q1 目标可判定性如何在不把目标形式化的前提下保证？**
过度形式化会让目标讨论变成填表，失去发现真问题的能力；不形式化又会导致验收争议。可能的出路：用"反例测试"代替形式化——要求目标所有者给出"什么情况算失败"的具体场景，而不是追求完备的判据体系。

**Q2 验收独立性如何结构性保证，而不是靠自觉？**
靠"要求验收者独立"是道德约束，不是结构约束。可能的出路：验收者由不同于执行者的入口进入（只读工件、不读执行对话）；高风险任务强制红队；验收记录公开可申诉。

**Q3 记忆晋升的证据门槛怎么定？**
门槛太低 → 过度泛化；门槛太高 → 经验无法沉淀。可能的出路：按"影响面 × 复现次数 × 反例强度"分级；L0 一律人类批准；先在小范围试用再晋升。

**Q4 技能与记忆的边界在哪里？**
"知道怎么做"与"会做"是两种知识。边界模糊会导致技能库塞满陈述性知识，或记忆里塞满流程。可能的出路：技能必须能被"照着做"，且带检查点；不能照着做的，一律进记忆。

**Q5 工作区状态的最小充分集是什么？**
状态太少 → 无法恢复；状态太多 → 维护成本高、容易腐败。可能的出路：只记录"恢复必需的"——当前阶段、进行中任务、阻塞点、下一步、最近验收——其余靠工件指针。

**Q6 人类门禁设在哪，如何防止形式化？**
门禁太多 → 人类成为瓶颈，开始橡皮图章；门禁太少 → 责任落空。可能的出路：只设三处（目标、争议、元知识晋升），且每次门禁必须留下"人类改了什么"的记录，没有修改也要说明理由。

**Q7 如何度量"进化"真实发生，而不是自我叙事？**
指标容易被游戏化。可能的出路：指标与事故/返工/接手时间绑定，而不是与"流程执行率"绑定；保留基线对照；允许指标被推翻。

**Q8 多 agent 结论冲突时谁裁决，裁决如何进入记忆？**
没有仲裁，冲突会以"各做各的"收场。可能的出路：按领域 owner 裁决；裁决写入决策记录（选项、理由、后果）；同类冲突重复出现时升级为规则或元知识。

**Q9 项目结束后，记忆如何归档、迁移、退役？**
不处理会导致"僵尸记忆"：过时但仍在被检索。可能的出路：项目收敛时做一次记忆清算——晋升、归档、标注失效；L2 随项目归档，L1 摘要进入组织层，L0 需重新验证。

**Q10 失败项目的教训如何避免被"成功叙事"覆盖？**
组织倾向于记住成功、遗忘失败。可能的出路：失败复盘与成功复盘同等地位；错误台账独立于项目叙事；"未采纳的建议"也要留痕。

**Q11 流程重量如何与任务风险匹配？**
用同一套重流程处理一切，必然被绕过。可能的出路：定义 2–3 档流程（轻/标准/严格），按风险选择，选择本身留痕。

**Q12 探索型任务如何改造这套工作流？**
探索型任务的目标在演化，验收对象不是交付物。可能的出路：验收"问题定义的清晰度、选项评估的充分性、下一步决策的依据"；记忆以"假设-证据-结论"为单位，而不是以"完成/未完成"为单位。

**Q13 偏差申报如何做到激励相容？**
自报偏差无收益、有成本，理性选择就是隐瞒；账本必然只剩被抓到的错误。可能的出路：自报偏差降低复核强度、隐瞒被查出加倍惩罚；把"申报质量"纳入验收者与执行者的共同评价。这是流程能否真实进化的隐藏前提。

**Q14 回退半径如何判定？**
什么情况下允许从 r1 升级到 r2/r3，谁批准，如何防止"目标通胀"？可能的出路：为升级设定证据门槛（如多条判据系统性不过、判据被证明不可满足），并要求 owner 签字与预算重估。

**Q15 解释负债如何度量与设阈？**
"读者重建成本小于重新推导成本"是原则，但缺少可操作的度量。可能的出路：用陌生读者测试的通过率、追问次数、分叉率作为代理指标；按任务风险设定不同的负债容忍度。

**Q16 否决记录如何被真正写下来？**
执行者天然倾向于记录"做了什么"，而不是"没做什么、为什么不做"。可能的出路：把否决记录列为任务卡的必填项；验收时检查"是否有至少一条被排除的选项及其理由"。

**Q17 验收标准的"出处独立性"如何实现？**
标准与任务同出规划者之手，盲点会同时流入执行与验收两侧；验收者独立，但验收依据不独立。可能的出路：高风险条目至少经非规划者视角复核；标准与任务分两阶段定稿；建立"标准判例库"供异源校验。

**Q18 进化环自身的收敛判据是什么？**
凭什么说系统在变好，而不是在堆积规则、放大偏见？可能的出路：把"错误复发率、规则冲突率、规则退役率、变更回滚率"作为进化健康度指标；设"归因不明→观察"类别，禁止强行归因；定期做"规则压力测试"。

**Q19 价值验收由谁、在何时执行？**
逐条验收只能验"符合契约"，验不了"适合目的"。可能的出路：价值验收由目标所有者或人类在收敛门前执行；高风险任务在方案门与收敛门各做一次；价值判断必须留下"接受/不接受"的明确记录。

**Q20 对抗性工件（记忆投毒、注入）在模型内还是外？**
工作区工件是共享读取面，一个被污染的条目可能跨任务传播。可能的出路：把"来源、置信度、写入者"作为记忆的硬字段；L0 晋升需人类批准；对抗性内容检测作为独立的守卫层，而不是工作流内的一个阶段。

## 2. 优先级：三个信任根 + 两个结构补丁

**P1 判据的信任根（Q1 + Q15）**
谁写判据、什么判据算合格、判据能否被产出方影响。目标不可判定只是其中一个表现；更根本的是判据的权威与质量。若判据可被产出方影响，验收即自证；若判据因果遥远，逐条验收只是把模糊切成更多模糊。

**P2 可续行（Q15 + Q16）**
接手是否真可行，取决于**否决记录**与**解释负债**，而不是产物多少。能恢复状态 ≠ 能续行：只存产物、不存"哪些路被排除、为什么"，接手者可能走向另一个分支，那是分叉，不是续行。

**P3 沉淀准入与淘汰（Q3 + Q9）**
进化机制一旦污染，越"进化"越僵化。晋升门槛、候选区、失效条件与退役机制，决定了这套系统是"越用越聪明"还是"越用越教条"。

**P4 验收独立性与外部信号（Q2）**
"高质量假象"的主要来源。同模型验收无法发现双方共享的错误前提，这是单模型体系的上限；程序性独立、红队、人类门禁与异构模型是唯一的外部信号来源。

**P5 约束、成本与不可逆动作（Q11 + Q13）**
没有预算、禁区、止损线与动作可逆性分级，系统只能因"做错"失败，不能因"太贵"或"不可逆"失败。偏差申报的激励相容也是这一层的问题：没有正收益，账本必然有偏。

**排序理由**：P1 不解决，P2/P3 都在为错误的标准服务；P2 不解决，P1 的成果无法被继承；P3 不解决，前两者会随规模劣化；P4/P5 是结构性补丁，可以分阶段补，但不能永远缺席。

## 3. 概念验证设计（不涉及技术实现）

概念阶段的验证不需要写代码，可以用纸面和角色扮演完成：

1. **纸面走查（Tabletop Walkthrough）**：选一个真实或虚构项目，按七段完整走一遍，产出目标契约、任务卡、验收单、错误台账、收敛报告，记录每一次"卡住"和"说不清"的地方。
2. **红队评审**：专门攻击目标契约与验收标准——找出可以被低成本满足的判据、可以被解释成"通过"的模糊表述。
3. **中断恢复演练**：走到一半强制中断，换一个新 agent 只读工作区继续；记录它问的问题，这些问题就是工作区的缺口。
4. **换人测试**：把同一张任务卡交给不同执行者，看产出差异；差异过大说明任务卡不够自包含。
5. **对照实验**：同一任务，一组走工作流、一组临时协作，比较返工率、验收争议、接手时间（概念级即可，不必精确量化）。
6. **冲突注入**：故意制造两条互相矛盾的记忆或两个冲突的验收结论，观察系统是否有仲裁路径。
7. **陌生读者测试**：让没有对话历史的 agent 只凭工件做下一步决策，与前任的决策对比；分叉即解释负债未清偿。
8. **删除测试**：逐类删除信息，看接手者的下一步是否改变；不改变的可删，改变了的必须保留。
9. **激励演练**：模拟"自报偏差"与"隐瞒偏差"两种策略，检验账本是否被生存者偏差污染。
10. **回退半径演练**：故意制造一次系统性失败，观察系统是就地消化、回方案、还是重谈目标；检验是否过度回退或回退不足。

## 4. 演进路线（概念级）

| 版本 | 内容 | 退出判据 |
| --- | --- | --- |
| v0.1 | 概念模型（本阶段） | 七段闭环自洽，漏洞清单成形 |
| v0.2 | 纸面走查与修订 | 走查中暴露的断点被补进模型 |
| v0.3 | 最小工件集与模板 | 模板能支撑一次完整走查 |
| v0.4 | 度量与实验设计 | 指标可采集、基线可对照 |
| v1.0 | 真实项目试运行（仍可不写代码） | 至少一次完整收敛 + 一次接手成功 |

**原则**：先验证概念，再谈实现。概念没跑通就进入实现，只会把概念漏洞固化成技术债。

## 5. 本阶段结论（与 REPORT 一致）

- 七个要点在概念上成立，但需要补：收敛判定、目标变更控制、冲突仲裁、生命周期与退役、人类门禁、度量、责任主体、回退半径、激励相容、部分通过/漂移。
- 七点不是线性七步：1–4 是主链阶段，5–7 是横切机制；纠错速度由最快回路决定，学习速度由最慢回路决定。
- 最大风险不是"agent 不够强"，而是**高质量假象**（F01+F04+F05）、**伪解耦**（F03+F16）、**过度泛化**（F08+F12）；这三类问题不会立刻报错，只会让系统在"看起来正常"的状态下慢慢失效。
- 解耦应以**解释负债**度量；可续行的关键不是产物齐全，而是**否决记录**与假设的保留。
- 必须承认一个上限：**流程抬高执行一致性，不抬高认知正确性**；同模型验收发现不了共享的错误前提。
- 下一步优先做三件事：判据的信任根（谁写、什么算合格）、可续行（否决记录 + 解释负债）、沉淀准入与淘汰；三者都不需要技术实现，适合在概念阶段解决。
