## 一、相对 v0.2：新增、冲突与修正

【确定】**新增**不是又加几个流程节点，而是三点：一是把目标所有者、主 agent、推演、计划、工作、验收、观测程序及异构模型放入同一权责生态；二是以工作区改动驱动分派；三是让交付物同时承担上游产物与下游工作焦点。阶段验收后的人裁、项目总验收及三环错误收敛，也使人类门禁和反馈层级比 v0.2 更具体。

【确定】**冲突**有五处：
1. v0.2 要求判据前置、方案门和失效控制，而“观测到改动即分派”若不受授权约束，会绕过这些门。
2. v0.2 的草稿、候选、待验收、失效等语义，无法被“已验收／进行中／错误返回”无损表达。
3. 工作 agent“负责验收”若指独立验收，违反验收独立；只能解释为自验。
4. “错误返回”若直接触发原执行者返工，违反 v0.2 的先归因后路由。
5. 异构模型若与人类共同拥有最终裁决权，会稀释人的目标与价值责任。

【推测】所需**修正**是：把 v0.2 的抽象“工件—门禁”具体化为“受权任务—钉定版本—分派—独立判定”回路；把三态降为对外摘要而非完整状态机；把观测程序限定为路由者；把主 agent 从实际总控收缩为目标澄清与汇总协调者。v0.2 的判据信任根、回退半径、记忆治理仍是前提，并未被新构想替代。

## 二、角色权限矩阵与主控制回路

| 角色 | 可以决定 | 不得单独决定 |
|---|---|---|
| 人类／目标所有者 | 目标、非目标、价值判据、重大基线变更、争议与遗留接受、最终完成；批准元规则变更 | 不应把形式签字当作已验证证据 |
| 主 agent | 澄清问题、组织推演、汇总分歧、提出协调建议 | 私改目标或判据、把汇总当裁决、独自宣布完成 |
| 推演子代理 | 提出解释、方案、反例及不确定性 | 把意见写成工程事实、直接派发实施任务 |
| 计划 agent | 将**已批准结论**分解为任务，声明依赖、输入输出、判据版本、风险与执行拓扑范围 | 采纳未决意见为基线、私改目标、批准自己的计划 |
| 工作 agent | 在任务授权内执行、自验、报告偏差、申请返工或漂移处理 | 独立验收自己、改判据、越权扩大任务或改变全局拓扑 |
| 验收 agent | 对封存版本作独立合规与集成判断，给出通过、部分通过、不可判定或退回建议 | 修改受验成果后仍充当独立验收者、作最终价值裁决 |
| 观测程序 | 发现改动，按既有计划提出或执行低风险路由 | 创造新目标／计划／判据、判定质量、处理元规则或不可逆动作 |
| 异构模型 | 提供异源质疑、完成度与偏离度复核 | 代替人类作价值选择，或以“第二票”掩盖共同错误前提 |

【推测】局部并行／串行可由工作 agent 在计划授权范围内选择；跨任务依赖、共享写范围或验收顺序的拓扑改变须回计划 agent，高风险改变须人裁。主 agent 不应成为所有信息的唯一转述者，否则既垄断解释权又构成故障单点。

**完整主链**为：目标讨论并形成目标契约 → 多席推演且标明事实、意见、假设和冲突 → 人类选定决策基线 → 计划 agent 形成任务及集成判据 → 观测门依授权分派 → 工作 agent 产出候选并自验 → 验收 agent 独立作阶段合规与集成验收 → 人类裁决争议、阶段通过及遗留 → 项目总验收同时检查完成度与偏离度 → 人类宣布完成并批准写回。计划只能先对未批准推演做“草案”，不得进入可执行基线。

失败不是一律返工：执行缺陷走 r1，分解或依赖缺陷走 r2，目标／判据缺陷走 r3，跨项目经验才走 r4。目标或判据改变必须使相关在途工作失效并重新绑定，而非静默继续。

## 三、交付物双重身份、三态与观测分派

### 3.1 “前景交付物”的可能解释

【存疑】它至少可能指：①当前注意力的工作焦点；②待处理的改动事件；③下游的输入上下文；④携带路由职责的控制令牌；⑤同一内容跨阶段的身份变化——对上游是产物，对下游是输入。五者不能混用：事件不是交付物，任务也不是交付物，当前焦点更不等于内容本身。

【推测】最自洽的是⑤为主、①为辅的**角色—版本关系**：上游形成的候选产物，经稳定性、可见性和依赖门检查后，成为某个已授权下游任务的“前景”，即当前工作所钉定的输入版本与目的。它不是一种新文件类别，也不因被观测就自动获得该身份。同一成果可在不同时间为不同任务提供前景，但每个前景必须对应明确消费者和任务；产物身份回答“由谁产生”，前景身份回答“现在谁依据哪个版本做什么”。

待人类确认：前景是否只接纳已验收输入，还是也允许候选／错误返回进入返工；一个交付物能否同时服务多个前景；前景究竟只是工作视图，还是还被赋予了调度权。本席建议分别为“允许但用途隔离”“可以但分别授权”“不赋予独立调度权”。

### 3.2 三态的合理位置

【确定】原三态并非同一逻辑维度：“进行中”描述执行，“已验收”描述判定，“错误返回”更像处置事件。因此它不能作为唯一状态机。【推测】可保留为**对外三态摘要**：已验收＝可作当前基线；进行中＝尚不可作已验收事实；错误返回＝已知不收敛且等待有主处置。内部另设相互正交的控制事实：生命周期（草稿、候选、待验收）、健康度（阻断、挂起、失效）、判定（部分通过、不可判定）及责任归属。

这样不是变相堆砌状态，而是避免把不同问题压进一个标签。尤其“已产出待验收”不能被写成已验收，“失效”也不是犯错，“部分通过”须保留逐项判据及剩余范围；只有人明确接受有限范围时，才可形成受限基线。已验收版本不得原地改写，后续修改产生新候选并重新验收。

### 3.3 观测—分派闭环

【推测】改动只是**分派提示，不是执行授权**。自动分派至少同时满足：任务已在批准计划内；输入版本稳定且用途可见；依赖仍有效；判据与目标未失效；责任唯一且无未决占用；同一工作范围与版本未被处理；写范围不冲突；动作可逆且风险在授权内。错误返回必须带归因、责任人和回退半径，不能由观测程序随机找人。

局部、可逆、重复性路由可自动；新增目标／计划／判据、跨边界共享写、不可逆动作及控制流改变必须人裁。如此才能避免重复与循环触发、脏读、多写者竞争和责任悬空。

## 四、三层验收、二维总验收与三环错误收敛

### 4.1 三层验收不是三次重复签字

1. **工作自验**：证明“我按任务做了、证据齐、已知偏差已报”，只负责执行完整性，不产生独立通过结论。
2. **阶段独立验收**：验收 agent 对钉定版本检查逐条合规、跨任务集成与相互污染；人类处理不可判定、争议和遗留接受。自验证据是输入，不是免验理由。
3. **项目总验收**：回到原始及现行目标、真实结果和非目标，异构模型负责异源挑战，人类负责价值与完成裁决。阶段全过只是总验收的必要证据，不是充分条件。

【确定】**完成度与偏离度不可合并**。完成度问“已承诺义务及证据覆盖多少”，偏离度问“实际结果离目标意图和价值多远”。清单全做而目标错误，是高完成、高偏离；只完成一部分但方向正确，是低完成、低偏离。单一分数会让前者被高完成掩盖，也允许用任务数量抵消价值偏差。总验收须分别给结论，且不得靠事后改目标抹平原目标偏离。

### 4.2 三环与三层的关系

三层验收是**发现与判定结构**，三环是**错误学习及变更权结构**，二者不是一一对应。自验、阶段验收、总验收及真实使用中的已发现偏差都进入一环；后续处置可能返回执行、计划、目标或元规则。

- **一环：显式报告**。【推测】“所有错误”只能定义为所有已发现且与目标、执行、判据或控制相关的偏差均留痕，不能承诺发现未知错误。观察层可广收并去重、分级通知，避免事件风暴；主动申报应降低非故意失误的额外成本，避免激励隐瞒。
- **二环：经验吸收**。语义归纳回答“发生了什么、属于目标／判据／计划／执行／约束／验收／观测哪层原因”；价值归纳回答“影响什么目标、是否复发、是否值得泛化”，不是把个人偏好升格为价值。所有错误可归纳，但只有经独立归因复核、样本与反例检查、适用范围及失效条件确认的候选，才可由相应权威升为约束；普遍或高影响约束须人批。
- **三环：元认知升级**。修改模型本身改变认知能力或先验，修改控制流改变角色、门禁、状态转移和回边；二者病因与风险不同，不能互相冒充修复。凡触及二者均交人类判断，agent 不得自行修改权重、元门禁或自己的授权边界；普通任务内参数调整不属此层。

结构回边因此为：一环向各验收层提供反证，二环经质量门改变未来任务分解、判据模板和约束，三环经人裁改变控制规则；技能化再影响后续执行。任何错误都不得直接跳成“已验收”或全局规则。

## 五、并行、技能、记忆与中断接手的最小规则

【推测】仅当输入与判据已钉定、依赖无先后、无共享写竞争、可分别验收且另有集成判据、成本与风险不升级时并行；否则串行。下游若必须消费未验收半成品，或动作不可逆、共享状态强耦合，则不能为速度伪并行。

高频只是技能化必要条件，还需跨情境稳定样本、明确检查点、失败模式、例外、失效与退役条件，并经人批准。**约束**规定必须遵守什么，**记忆**保存证据、决策与背景，**技能**组织可重复动作；同一规范只维护一个权威出处，技能和记忆引用它，规范变化须触发相关技能复审，禁止双账漂移。

中断后只读工作区者至少应能重建：原始／现行目标与非目标、已批准及被否决方案及理由、任务依赖和下一动作、交付物版本与可见性、判据版本及已有验收证据、责任与阻断、错误归因及回退半径、约束预算和适用技能／记忆版本。最低测试是答清“为何做、做到哪、下一步、怎样算完成、什么不能再做、争议找谁”，否则不算可接手。

## 七、先自我反驳

【推测】**反驳一：人类门禁过多会重造瓶颈。** 成立，因此只把目标、价值、重大判据、不可逆动作与元变更保留为硬门；低风险局部分派可预授权。但人手不足时应挂起或缩小范围，不能让 agent 代决。

**反驳二：外部三态加内部事实只是把复杂度藏起来。** 若内部维度无消费者，确属过度设计；只保留能改变授权、消费或恢复决策的信息。对外摘要可粗，对责任与验收证据不可粗。

**反驳三：工件中心无法传递默会意图，角色隔离也不产生认识论独立。** 完全成立。本方案只降低解释负债和自证风险，讨论、人类判断、真实结果与异源挑战仍不可删除。

**反驳四：小项目采用观测分派和全套角色比直接执行更差。** 也成立；此时应退化为轻量人工链路，而非为了生态完整制造角色。

## 八、真正优异点、不成立条件与边界

【推测】真正创新不是多角色流水线，而是**以钉定交付物连接责任交接，并让改动路由受既定授权约束，同时让错误能受治理地回写控制结构**。若只是“文件变了就呼叫另一个 agent”，只是自动化流水线，且更脆弱。

优点成立需要：目标可分解、判据可信、版本可区分、验证成本低于返工成本、人类门禁真实、任务经验值得复用。适合长周期、多会话、需审计接手且动作多可逆的工程。目标高度探索、强实时、任务不可分、反馈晚于工程、验证极贵、一次性小任务或高度共享写场景中，应收缩或不用；高不可逆风险场景只能采用强人裁的严格子集，不能自动分派。

## 九、最需要人类裁决的五问与 v0.3 最小基线

1. **前景交付物是否采用“角色—版本—任务关系”定义？** 候选与错误返回能否成为前景，须明确用途隔离。
2. **哪些推演结论必须批准后才能进入计划？** 本席建议：任何会成为执行基线的结论均须人批，未批准内容仅可进入不可派发草案。
3. **三态是否仅作对外摘要？** 必须确认待验收、失效、挂起和部分通过不会因摘要而丢失。
4. **自动分派的授权边界到哪里？** 建议仅限已批准计划中的局部、可逆、低风险和依赖有效任务。
5. **总验收与元变更是否由人类独占最终权？** 建议异构模型只有独立建议权；模型本身、控制流及高影响约束变更均须人裁。

**建议的 v0.3 最小基线**：①目标与价值权归人，主 agent 只协调；②推演到计划之间设决策基线门；③任务钉定输入、判据、责任、依赖、风险和回退半径；④自验、独立阶段验收、人类总验收权责分离；⑤交付物双重身份按版本化交接解释，三态仅作摘要；⑥观测提示与执行授权分离；⑦完成度、偏离度双轴报告；⑧错误观察广收、约束晋升严审、元变更人裁；⑨技能有样本、失效、复审与退役，规范单一出处；⑩以只读工作区接手测试检验整个闭环。

## 十、收敛结论

【确定】新构想使 v0.2 的角色与反馈更具体，但原样采用三态和改动即分派，会直接破坏其门禁与一致性前提。【推测】可行的 v0.3 应是“**人类定权、计划授权、交付物钉版、观测路由、独立验收、归因回退、经验受审晋升**”的闭环，而非主 agent 统领的自动生产线。它提高的是可追踪性、执行一致性和可恢复性，不保证目标正确，也不能替代真实结果与人类价值判断。
