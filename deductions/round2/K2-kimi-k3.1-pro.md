> 输入依据：仅 [BRIEF-v2.md](../../BRIEF-v2.md) 与 [REPORT.md](../../REPORT.md)；未读取其他席位的本轮产出。

## 一、总判断及相对 v0.2 的变化

【确定】新构想的主要推进不是增加若干 agent，而是尝试把**权威判断、工件流转、错误学习**合成一个生态。它仍不是天然闭环：工件变化只能提供“发生了什么”的信号，不能提供“应当做什么”的授权；验收结论只能证明特定判据下的证据充分，不能自动证明目标有价值。

**新增**有五项：一是主 agent、推演、计划、工作、验收、观测程序、异构模型被赋予不同位置；二是增加阶段人类裁决与人—异构模型总验收；三是交付物同时承担协作焦点与成果载体；四是程序由工作区改动触发分派；五是错误被分为报告、经验吸收、元认知升级三环。

**冲突**有六项：

1. v0.2 要求独立验收，新构想却说工作 agent 对自己结果“负责验收”；应把后者收缩为自验，不产生“已验收”权。
2. v0.2 已有候选、挂起、失效、部分通过等语义，三状态不能取而代之。
3. v0.2 禁止未验收产物被下游当作事实，新构想却可能让任何改动触发消费；必须区分“观测到草稿”与“授权下游采用”。
4. v0.2 要求先归因再路由，“错误返回”不能天然等于退回原执行者。
5. v0.2 的沉淀准入是严进，二环若把“所有错误”直接反馈为约束，会重新打开污染通道。
6. 主 agent 同时澄清、汇总并推动计划，可能形成比 v0.2 更明显的单点权力。

**修正**则是：把 v0.2 的收敛门展开为阶段裁决与项目总验收；把异构模型引入外部质疑，但它仍不是价值裁决者；把技能化的人类批准设为必要条件而非充分条件；把v0.2“未验收产物不得读取”的绝对表述修为“不得作为已成立依据”，探索性阅读可以存在，但必须保留不确定性与失效传播。

## 二、角色权限与主控制回路

【确定】权限应按“能否改变他人义务”划分，而不是按 agent 名称划分。

| 角色 | 可以决定 | 不能决定 |
|---|---|---|
| 人类／目标所有者 | 目标、非目标、价值取舍；重大判据与计划变更；争议、遗留风险、元规则及最终完成 | 不能以签字替代证据，也不能把最终责任转给 agent |
| 主 agent | 组织澄清与推演，保留分歧，提出协调和路由建议 | 不得独自批准目标、把意见变事实、改判据或宣布完成 |
| 推演子代理 | 提假设、备选、反例与置信度 | 不得直接任务化、派发或验收 |
| 计划 agent | 在授权内分解任务、排列依赖、拟初始拓扑并操作化判据草案 | 不得擅定价值取舍，隐藏未裁决前提，或借重排计划改目标 |
| 工作 agent | 在任务边界内选方法、自验、申报偏差；在授权范围内局部并行 | 不得独立验收、改目标判据或改变跨任务拓扑 |
| 验收 agent | 对冻结候选作合规、集成判断，给出通过／部分／拒绝／不可判定及归因建议 | 不得一边修补一边裁判，不得改判据或作最终价值验收 |
| 观测程序 | 发现变化，依既有授权提出或执行低风险分派 | 不得创造工程前提、解释价值、改优先级授权或宣布通过 |
| 异构模型 | 对完成证据、目标偏离和共同盲区提出独立质疑 | 不得单独批准完成，也不因“异构”自动成为真理来源 |

【推测】初始执行拓扑由计划 agent 决定；工作 agent 只能调整不改变依赖、写权限、验收顺序及风险预算的局部次序。跨任务改拓扑由计划 agent 重议；显著改变成本、风险或范围则回人类。观测程序永远不是拓扑权威。

完整主链为：**目标 → 主 agent 澄清与推演 → 人类判断关键前提 → 计划及判据前置 → 依依赖派发执行 → 工作自验并提交候选 → 阶段独立验收 → 人类阶段裁决 → 后续阶段 → 人与异构模型总验收 → 人类宣布完成**。

推演结论不应一律等待逐项批准，否则人类成为瓶颈；但涉及目标、价值、相互矛盾的假设、不可判定的判据或不可逆动作时，必须先裁决。可核验事实可在既有授权内进入计划，未决假设只能生成“探索以消除不确定性”的任务，不能伪装成工程事实。

## 三、交付物双重身份、三状态与观测分派

### 3.1 “前景交付物”的可能解释

【存疑】该词至少可能指：①当前注意力和行动焦点；②某任务的输入上下文与基线；③改动后形成的待处理事件；④等待下游处理或验收的候选成果；⑤兼具上述作用的调度单位。若直接把它等同于交付物本身，会把内容、事件、任务和授权混为一谈。

【推测】最自洽的解释是：**前景不是交付物的固有属性，而是“某交付物的确定版本，在某任务中对某角色构成的已授权工作焦点”**。它既指出处理对象，也指出为何此时处理、依据何判据处理。其“产物”身份承载内容，“前景”身份承载控制关系。同一成果可以是上游产物、下游前景，但原始改动事件不是前景，全部相关记忆也不应自动塞入前景。

待人类确认：前景是否只表示注意力，还是同时包含行动授权；草稿能否成为仅限原责任人的前景；一个交付物能否同时对多个角色为前景。

### 3.2 三状态：保留外观，不能承担全部控制

【确定】“已验收、进行中、错误返回”并非同一逻辑维度：前者是评价结论，中者是责任履行状态，后者是路由结果。直接组成状态机至少产生三处空洞：已提交待验收无处安放；挂起、阻断、失效被伪装成进行中；错误返回不知退给谁、为何退、何时停止。

因此三状态最多作为面向人的外部摘要，内部还需区分：**产物可见性**（草稿、候选、已验收、被取代／失效）、**工作控制**（待办、进行、待验收、阻断、挂起、返回）以及**验收判定**（通过、部分通过、拒绝、不可判定）。已验收必须绑定确定版本；错误返回必须绑定原因、回退层级、责任人与重试边界，而非成为垃圾桶。

### 3.3 观测—分派闭环

【确定】合法分派至少需要：改动达到预先声明的可消费成熟度；输入与判据仍有效；没有等价的在途责任；有唯一责任归属；依赖和共享写权限允许；该路由已经授权。重复通知不应产生重复义务，处理过程中发生的新改动应形成重新绑定或失效判断，不能被静默并入旧验收。

低风险、可逆、已有计划的后续任务可自动分派；新目标、新判据、新责任域、不可逆动作、元规则及超出成本风险边界必须过人类门禁。连续返回、循环触发或无主错误应停止自动扩张并升级，而不是再制造一轮 agent 活动。

## 四、三层验收与三环错误收敛

### 4.1 三层验收不可互相吸收

1. **自验**回答“我是否按任务做完、证据是否可复现、已知偏差是否报告”，产物只是候选。
2. **阶段验收**由独立角色检查逐条契约、跨产物集成和阶段目标，再交人类裁决争议、例外与价值取舍。程序性独立不等于认识论独立。
3. **总验收**同时检查项目级完成度、目标偏离度、整体副作用与遗留接受；异构模型负责挑战，人类负责价值与完成宣告。

【确定】完成度是“已批准契约及证据闭合到何种程度”，偏离度是“实际结果与当前真正目标、价值及非目标相距多远”。错误目标可被百分之百完成而严重偏离；探索原型也可能完成度低却方向偏离小。合成一个分数会让高完成度抵消价值失败。总验收必须同时阅读目标沿革、否决记录和遗留异议，防止只证明清单做完。

### 4.2 三环不是三级自动升级

- **一环：显式报告。**【确定】“所有错误”只能指所有已发现且具有控制意义的错误、偏差和不可判定项，不能承诺发现未知错误。原始观察可广收，升级应按影响归并；善意自报应降低而非增加责罚，隐瞒才承担额外后果。
- **二环：经验吸收。**语义归纳是判断发生了什么、因果属哪层、适用条件和反例是什么；价值归纳是判断该错误有多重要、应牺牲何种成本避免、是否值得形成约束。后者包含规范选择，不能由统计频率自动推出。经验先为候选，经独立归因复核后才可影响任务、门禁或判据模板；普遍约束及价值性约束须人类批准。
- **三环：元认知升级。**局部执行方法调整不等于修改控制流。凡改变模型本身、角色权限、人类门禁、验收独立性、目标判据权威、报告与审计机制，均只能由 agent 提议、人类判断；系统可以紧急停止或退回已批准安全基线，但绝不能自行扩权或削弱否决点。

结构回边应按归因进入：执行缺陷回任务返工（r1），分解或依赖缺陷回计划（r2），目标／判据失配回人类重订目标（r3），跨项目稳定教训才回技能、记忆与控制规则（r4）。三层验收不断产生一环信号，二环提供受控学习，三环决定能否改变主回路；不能把“返回原工作者”当作唯一反馈。

## 五、并行、技能、记忆与中断接手

【确定】并行的前提不是“有多个 agent”，而是输入基线稳定、依赖无环、写入不重叠、能够分别验收且保留集成检查。输出会相互改变前提、共享写权限、后续不可逆动作依赖前序裁决，或并行合并成本高于收益时，应串行。成本与风险能改变拓扑，但不能取消必要门禁。

技能化须同时满足高频、跨样本稳定、动作相对明确、结果可检查、失效模式已知；人类批准只是最后门禁。技能必须有适用范围、例外、失效、复审与退役。**技能**是可复用动作程序，**约束**是必须服从的规范，**记忆**是带来源与置信度的经验证据。单一出处指同一命题只有一个权威来源：技能引用约束，记忆提供证据，不另维护三套相互漂移的真理。

中断后，新 agent 只读工作区至少需要：当前目标、非目标与基线；任务依赖和当前前景；各候选／已验收版本；判据、证据及验收异议；责任人、挂起原因与下一合法动作；关键假设、人类裁决、否决及未解决分歧；已试修复、未决错误、剩余成本风险授权，以及哪些内容已经失效。缺少“为何不采用其他路径”，接手只会重复历史。

## 六、失效模式

| 编号 | 触发条件 | 后果 | 严重度 |
|---|---|---|---|
| F01 | 主 agent 同时解释目标、筛选推演并推动计划 | 分歧被摘要吞没，形成单点误判与隐性代决 | 高 |
| F02 | 未批准或互相矛盾的推演被任务化 | 全链高效执行未经成立的前提 | 高 |
| F03 | 判据后置，或执行者据结果调宽判据 | 验收变事后合理化，出现全绿假象 | 高 |
| F04 | 草稿或半成品改动即触发下游 | 脏读、错误传播、返工扩散 | 高 |
| F05 | 重复事件、互写产物或完成通知再次触发同类任务 | 事件风暴、重复劳动、自动循环 | 高 |
| F06 | 多写者并行且共享对象无唯一责任 | 覆盖、合并冲突，证据与版本错配 | 高 |

| F09 | 阶段只逐条验收而无集成检查 | 每项通过、整体不可用 | 高 |

| F17 | 接手缺少基线、否决记录或未决异议 | 重复旧错、误续已失效工作 | 高 |
| F18 | 提交后交付物或证据仍可静默变化 | 验收对象变形，已通过结论失去所指 | 高 |

## 七、真正优异点、不成立条件与适用边界

【推测】真正优异点不是“多 agent 自动化”，而是四种结合：以交付物版本降低对话接力损失；以角色权限分离生产与裁判；以阶段／总验收连接局部合规和整体价值；以三环把即时纠错、组织学习和元规则变更区别开。若这些门禁真实存在，中断接手与责任审计会成为可检验能力。

【确定】若人类没有实际判断能力或时间、判据不可判定、产物无法形成稳定证据、责任不可归属、真实反馈长期缺席，则该生态不成立，只会更精细地制造流程外观。它适合长周期、多阶段、需接手审计、返工代价高于控制代价的工程；对一次性小任务、强实时任务、高度开放创意、不可分整体判断，应降级或不用。自动观测分派单独看只是普通流水线，三状态和三环命名本身也不是创新。

## 八、自我反驳

1. **反驳：内部状态增多会重新制造复杂性。**成立；若把每维都变成繁复流程，收益会被管理成本吞没。但“待验收、失效、阻断”是现实存在的控制事实，不能为保留三态而否认。折中是外部仍三态，内部只保留会改变下一步合法性的最少事实。
2. **反驳：人类门禁过多会成为单点瓶颈。**成立；因此不是每个推演、每次返工都报批，而采用既有授权与风险分级。但目标、价值和元规则没有可替代权威，人类缺席时应暂停而非模拟批准。
3. **反驳：异构模型未必真正独立。**成立；共同语料、错误判据与目标框架仍可造成同源结论。所以它只是抗盲区信号，不能替代真实使用结果与人类价值判断。
4. **反驳：工件驱动未必优于显式任务调度。**在稳定、短链、低风险场景确实未必。其价值只在工件能同时降低解释负债、明确版本责任和支撑接手时成立；否则事件驱动只是额外耦合。
5. **反驳：二环严进会漏掉宝贵教训。**可能，但漏掉一条观察可再收集，错误普遍约束会污染多轮决策；应“观察广收、规则严进”，而非在 recall 与 precision 间只选一边。

## 九、最需要人类裁决的五个概念问题与 v0.3 最小基线

1. **前景交付物究竟是什么？**建议确认为“绑定角色、任务与版本的授权工作焦点”，不是原始事件或全部上下文。
2. **三状态是对外摘要还是完整状态机？**建议仅作摘要；已验收权属于谁、部分通过与失效如何呈现须明确。
3. **哪些事项必须人类显式批准？**建议限定目标／价值／重大判据、不可逆动作、争议例外与元规则，其余可在成文授权内自动执行。
4. **总验收如何分工？**建议人类作价值与完成裁决，异构模型只有质疑和建议权；完成度与偏离度不得互相抵消。
5. **二环与三环的权界在哪里？**建议明确哪些经验可成为局部建议、哪些约束须人批，以及“修改模型本身”和控制流变更均不得自动扩权。

**建议的 v0.3 最小基线**：保留一个目标所有者；主 agent 无最终批准权；计划只消费已批准前提或显式探索假设；判据前置且版本绑定；自验不产“已验收”；阶段独立验收后由人裁决，总验收双报完成度与偏离度；交付物区分版本可见性、工作控制与验收判定；观测程序只执行已授权、可去重、可停止的分派；错误先归因再回退，经验晋升受独立复核，元规则只由人类改变；技能与记忆可追溯、可失效、可退役；工作区足以支持无对话接手。

## 十、收敛结论

【确定】新构想应被收缩为**“人类保留规范权威、交付物承载可验证据、观测程序仅传递已授权义务、三环反馈受独立质量门约束”**。它相对 v0.2 的真正增量是角色—工件—反馈之间的显式关系，而非三状态或自动监听。

【推测】按上述最小基线，它能提高执行一致性、接手能力和跨阶段纠错能力；不能保证目标正确，也不能凭异构模型消除共同盲区。若坚持“三状态即完整状态机”“任何改动自动分派”“所有错误都形成约束”或“主 agent 汇总即可替代人类裁决”，则 v0.3 比 v0.2 更危险，因为它会用更活跃的自动化掩盖同一组信任根缺口。
