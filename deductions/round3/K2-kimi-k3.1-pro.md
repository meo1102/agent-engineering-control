# AECW 第三轮独立推演（K2）：权责制衡、验收独立性与冗余收缩

> 席位：K2　审视重点：角色权责、主 agent 隐性代决、人类裁决预算、验收独立性与重复环节  
> 范围：仅作概念推演，不涉及技术实现、选型、代码、接口或存储格式。  
> 材料边界：只依据第三轮任务书及 v0.2、v0.3 两份共同报告；本文是独立概念判断，不把多席一致当作事实验证。

## 0. 阅读约定与置信度

本文使用三种标记，避免把逻辑必然、机制推断和待裁事实混为一谈：

- **【确定】**：由本轮目标、概念定义或权责关系可以直接推出的结论；它是概念上的确定性，不表示已经过现实项目验证。
- **【推测】**：对 agent 或人类在流程中的行为、激励和失效倾向作出的有理由推断，实际强度需要项目经验检验。
- **【存疑】**：取决于人类价值选择、项目情境、真实用户、反馈周期或运行事实，本文不能替相关权威定案。

另有一项证据边界必须先说清：**【确定】本文能够分析任务书是否要求“最大推理强度”，却不能仅凭文本证明运行元数据实际满足该要求。四席共享材料、同模型两席也不构成充分异构验证。** 因而下文的高置信结论主要来自权责矛盾的可推导性，而不是来自席位数。

## 1. 一句话总判断，以及对 v0.2/v0.3 的继承、冲突与修正

**一句话总判断：本轮构想应被收缩为“人类保有规范权威与最终责任，主 agent 只协调而不定权，计划只在授权内任务化，工作完成只取得提交资格，验收直接依据目标对工作区取证，真实使用与遗留人裁共同构成全量验收，泛化学习只在已验收基线封存后受审发生”的受权交付闭环；否则角色、文档和门禁越多，越可能把主 agent 的隐性代决、人类橡皮图章与全绿假象制度化。**

### 1.1 必须继承的内容

【确定】从 v0.2 应继承判据信任根、目标合规与价值验收分层、程序性独立、工作区一致性、回退半径、组合性盲区、记忆与技能治理以及真实外部信号。从 v0.3 应继承主 agent 协调而非代决、计划不得借任务化扩权、交付物版本与消费资格、自验不等于独立验收、阶段验收必须包含集成和目标对齐、完成度与偏离度不可互抵，以及人类裁决预算是有限资源。

这些不是可随流程精简而删除的装饰。它们分别回答“凭什么判”“谁来判”“判的是哪个版本”“局部完成后能否合法向上推断”“谁能承担最后责任”。删除其中任何一项，都会让另一环节被迫回答自己无权或无能力回答的问题。

### 1.2 本轮相对前两轮的实质推进

【确定】本轮有三项真正增量：

1. **文档“写完”与“可供特定下游使用”被分开。** 这使目标文档和开发任务文档从作者产物变成受控授权依据。
2. **验收依据从任务清单回升到目标，并直接落到工作区。** 这正面攻击“任务全绿而整体不可用”。
3. **项目末端引入真实使用，并把泛化学习放到全量验收之后。** 前者补足价值与使用证据，后者试图防止开发中的局部经验过早污染项目基线。

【推测】如果这三项被认真执行，本轮会比单纯增加 agent 数量的方案更能减少交接失真；如果只是增加“文档已交付”“阶段已验收”“真实使用已通过”等标签，则只会增加高质量假象的层数。

### 1.3 必须公开修正的四处冲突

**第一，v0.2 的“收敛包含记忆写回”与本轮“全量验收后才经验收敛”存在时序冲突。**【确定】若全量验收仍以记忆写回为前置条件，而记忆写回又以全量验收为前置条件，就形成循环门槛。本轮应明确：**项目全量验收先冻结项目基线，经验收敛与模型进化是其后独立活动，不再是项目完成的组成条件。**

**第二，v0.2/v0.3 的错误反馈横切全程，不能被解释为本轮禁止开发期纠错。**【确定】应收缩的是跨任务泛化、长期约束晋升、技能化、长期记忆改写以及模型或控制流进化，而不是观察、报告、局部返工、阻断和止损。

**第三，v0.3 的项目总验收不能只是一次价值报告。**【确定】本轮明确要求真实使用，因此真实使用证据是总验收的核心组成，而非总验收之后可选的附加展示。

**第四，“验收 agent 联合人类在各个阶段验收”若被理解为人类每次重复签字，就与人类裁决预算冲突。**【推测】高密度重复签字会促使人类依赖摘要和默认选项。本文建议把“联合”解释为：人类预先给出价值和授权边界，阶段中出现目标、价值、例外、不可逆后果或遗留接受时实际裁决；常规事实核验由独立验收完成。最终真实使用后的项目完成仍必须由有权人类决定。这是否符合原构想的人类参与强度，属于【存疑】，需人类定稿。

## 2. 完整的“人类—agent 群落—项目工作区”框架

### 2.1 三元结构不是三个平级决策者

【确定】三元结构的合理关系不是“人类提目标、agent 做事、工作区存文件”这么简单，而是：**人类提供规范权威，agent 群落提供受权的认知与执行劳动，工作区提供可检查的项目对象和证据环境。** 三者不能互相借壳取得对方的权力。

| 核心 | 不可转移的责任或功能 | 能授权什么 | 不能由他者冒充什么 |
| --- | --- | --- | --- |
| 人类／合法目标所有者 | 确定目标、非目标、价值取舍、风险偏好和授权；解决规范冲突；接受其有权接受的遗留；宣布最终完成；决定元规则变更 | 允许 agent 在明确范围内作事实判断、局部可逆执行和例行协调 | 不能用 agent 的一致意见代替价值选择，也不能用签字代替事实证据 |
| agent 群落 | 澄清、草拟、分解、执行、自验、独立取证、报告偏差与不确定性 | 各角色只能传递自己实际持有的有限权限 | 不能把文本流畅、角色一致或任务完成冒充人类授权、真实价值或项目完成 |
| 项目工作区 | 承载目标与任务基线、实际产物、版本关系、证据、否决和争议历史；支持直接检查、协作与接手 | 让有权者能够检查“记录了什么、提交了什么、实际运行了什么” | 不能自我证明记录必真、证据完整、外部影响不存在、用户已经受益或人类已经接受 |

工作区可以同时是**生产环境、证据源、协作媒介和审计记忆**，但只能是“有条件的事实源”。【确定】它能权威回答“哪份目标被记录为现行基线”“哪个候选被提交”“某项裁决留下过什么理由”，却不能仅凭自述回答“这个功能真的可用”“用户真的完成了真实任务”“副作用已被充分发现”。

【推测】最危险的工作区不是缺少文档，而是文档极其完整、实际产物也经过布置，使验收者把“工作区内部的自洽”误认成“目标世界中的成立”。因此，直接检查工作区是必要条件，不是充分条件；真实使用之所以重要，正因为它可能提供不同于作者自述的外部信号。

### 2.2 四类权力必须先分开

【确定】角色权责不应按“谁更聪明”划分，而应按谁能改变他人义务划分。至少有四类权力：

1. **规范决定权**：决定想要什么、何者更重要、哪些风险可接受、谁可以行动。原则上属于有权人类。
2. **证据判定权**：判断某项主张在指定判据和范围内是否有足够证据。可由独立验收 agent 承担，但不能借此改变目标。
3. **执行选择权**：在既定目标和授权内选择局部做法。计划 agent 和工作 agent 可分别拥有不同层级的执行选择权。
4. **协调路由权**：组织材料、提示冲突、交接版本、把问题送给有权者。主 agent 主要持有此权；路由不等于批准。

【确定】一个角色拥有后两类权力，并不自动获得前两类权力。尤其“能写出最完整摘要”不等于“能决定摘要中的争议”，“能判断证据不足”不等于“能降低目标让证据变足”。

### 2.3 各角色的权限、责任与禁区

| 角色 | 应当负责 | 可以独立决定 | 不得单独决定 |
| --- | --- | --- | --- |
| **主 agent** | 与人类澄清目标；形成目标文档候选；保留歧义、分歧、被否决选项和裁决请求；协调交付 | 在既有授权内组织讨论、汇总事实、提示风险、安排交接；对纯协调事项作可逆选择 | 私定目标含义、选择价值取舍、压低判据、批准自己起草的文档、把摘要当裁决、宣布阶段或项目完成 |
| **计划 agent** | 把有效目标文档转为阶段与开发任务文档；说明依赖、任务边界、输入版本、预期产物、集成要求和目标映射 | 在授权内分解任务、安排先后与并行关系、细化不改变目标的操作判据、提出计划层返工 | 把未裁决假设当事实、为可执行而软化目标、新增价值承诺、扩大写域或风险授权、批准自己的高风险计划 |
| **工作 agent** | 按任务授权执行；保存实际产物和自验证据；申报偏差、阻断与未知；在超界时停止 | 选择不改变跨任务义务的局部执行方法；自验；申请返工或升级；把任务标为“执行完成／待独立验收” | 独立验收自己、改目标或任务判据、把任务完成传播成阶段完成、处理超出授权的不可逆行动 |
| **验收 agent** | 对指定版本的文档可用性、阶段产物和最终证据作独立判断；直接读取目标与工作区；报告合规、集成、偏离、证据缺口和遗留 | 在既定判据内作证据判定；要求补足证据；提出归因与回退建议；把规范争议提交人工审判 | 修改受验对象后仍自称独立裁判、改写判据、接受价值例外或最终遗留、以自身判断替代真实使用、宣布最终项目完成 |
| **人类／目标所有者** | 提供目标与授权；裁决规范冲突；评价真实使用价值；接受有权接受的遗留；承担最终完成与元变更责任 | 在合法权限内作价值与风险选择；调整目标但保留沿革；撤销或收缩授权 | 不能靠事后改目标抹平原偏离，也不能替无授权第三方接受损害，更不能把“已批准”当作“事实已证明” |

【确定】主 agent 与验收 agent 的必要分离，不是因为两个名字更正式，而是因为主 agent 参与目标文档生产、选项构造和状态叙述；若再由其决定这些产物是否可用，就把作者权、信息选择权与裁判权合并了。

【推测】验收 agent 自身也可能通过判据解释取得隐性规范权。例如把“易于使用”解释成某个极窄场景，再据此给出通过。因此“验收不得修改判据”还不够，**凡有多种合理解释且选择会改变价值或风险分配的，都应暴露为解释分歧，而非包装成单纯事实判断。**

### 2.4 权责制衡的五条硬边界

1. **作者不单独授予自己产物的消费资格。** 主 agent 和计划 agent 都可以宣布草稿完成，但不能仅凭宣布使其成为下游的已授权依据。
2. **证据判定不改变规范。** 发现目标不可达、使用不便或成本过高，可以触发重议，不能由验收者或计划者自行降标。
3. **修复者不得把同一版本的修复与独立裁判合并。** 验收 agent 若参与修补，该版本至少需要重新取得独立判断；更简洁的做法是把修复交回工作 agent。
4. **沉默不是批准，摘要不是原始证据。** 人类未回应不能默认扩权；验收者、异源挑战者和最终人类应能触及原始目标、实际产物及异议。
5. **任何完成标记只覆盖其语义范围。** 文档通过、任务完成、阶段可继续、当前可用和项目完成是五种不同主张，不允许逐级自动升级。

## 3. 交付关系与端到端控制主链

### 3.1 主链不是“文档接力”，而是“有限授权接力”

【确定】完整主链可表述为：

**人类提出目标与边界 → 主 agent 形成目标文档候选并暴露未决项 → 人类确认规范内容、独立视角检查文档可用性 → 计划 agent 仅依据有效目标形成开发任务文档 → 任务文档取得指定用途的消费资格 → 工作 agent 执行、自验并提交项目产物候选 → 验收 agent 联合人类按阶段依据目标直接检查工作区 → 各阶段形成受范围限制的集成与可用性证据 → 项目末端以真实使用为核心进行总验收 → 有权人类在偏离、遗留和副作用显式呈现后决定是否完成 → 冻结已验收基线 → 另行开展经验收敛和模型进化。**

这里每一次“交付”授权的都不是绝对真理，而是一个有限动作：

- 目标文档交付，授权计划者在指定版本和边界内任务化；不授权其重定义价值。
- 开发任务文档交付，授权工作 agent 在任务范围内行动；不授权其改变跨任务目标或自我验收。
- 工作产物交付，授权独立验收者检查候选；不授权下游把候选当已验收事实。
- 阶段验收交付，授权后续阶段在已验范围和仍有效基线上继续；不授权最终完成。
- 总验收交付，向人类提供完成与偏离证据；是否接受遗留、是否宣布完成仍是规范决定。
- 全量验收后的基线交付，只允许开始受审的经验分析；不自动授权任何模型、技能或控制流变更生效。

### 3.2 五类交付物的关系

| 交付物 | 回答的核心问题 | 形成者 | 必要的独立检查 | 能支持的下游主张 | 不能证明 |
| --- | --- | --- | --- | --- | --- |
| 目标文档 | 为何做、要什么、不做什么、价值与边界是什么 | 主 agent 草拟，人类定权 | 人类确认规范含义；独立视角检查是否可理解、可判定、可供计划消费 | 计划任务化的合法依据 | 项目已经值得做、目标必能达成、产物已经可用 |
| 开发任务文档 | 如何在不改变目标的前提下分工、分阶段和取证 | 计划 agent | 检查目标映射、范围、依赖、集成要求及下游可理解性 | 工作 agent 的有限执行授权 | 任务执行必然产生目标价值，局部通过可推出整体可用 |
| 项目产物 | 工作区中实际形成了什么 | 工作 agent | 工作自验后，再由独立验收对实际候选取证 | 阶段验收与真实使用的对象 | 作者自述完成就等于独立通过 |
| 阶段验收结论 | 当前版本的局部合规、集成、目标轨迹和阶段可用性如何 | 验收 agent，人类处理规范事项 | 直接对照目标和实际工作区，不只核对任务清单 | 限定范围内的后续消费与继续开发 | 最终目标闭合、真实用户获益、遗留可接受 |
| 总验收与真实使用结论 | 目标义务、整体使用、偏离、副作用和遗留是否足以支持完成决定 | 验收 agent 报告证据，真实使用提供信号，人类作最终决定 | 原始目标与沿革、跨阶段集成、真实使用、未决异议和遗留必须可见 | 人类作出完成、限制完成、继续或终止的决定 | 永久正确、所有环境可用、未来变更无需再验 |

### 3.3 版本与用途是交付关系的一部分

【确定】“目标文档通过”“任务文档通过”若未指明版本、消费者和用途，语义就不完整。一个版本可供计划 agent 分解，不一定可供最终用户理解；一个任务文档可供探索，不一定可供不可逆执行。旧版本的通过结论也不能自动附着到修改后的内容。

【推测】若状态只挂在文档名称上，而不挂在“版本—用途—判据”关系上，项目会频繁出现“它以前不是通过了吗”的争议，并最终以旧通过掩盖新漂移。版本钉定不是额外文书工作，而是使验收结论有稳定所指的最低条件。

### 3.4 目标变更不能靠交付链悄悄完成

目标文档可以有原目标、现行目标和变更沿革。【确定】合法变更不会抹掉历史：后续任务应重新绑定现行目标，验收应同时说明原承诺、现承诺以及变化理由。否则，计划 agent 可以通过分解、工作 agent 可以通过偏差申报、主 agent 可以通过摘要、最终人类可以通过事后改目标，共同把偏离洗成成功。

【存疑】哪些目标调整属于正常澄清，哪些属于需要重新人裁的实质变更，不可能只靠文字差异判断；其核心是是否改变价值取舍、义务范围、风险承担或授权边界。

## 4. 五种文档判定的语义边界及状态维度

### 4.1 五态首先作用于“某版本对某用途的可用性判定”

【确定】通过、部分通过、拒绝、人工审判、待判定不应描述作者是否辛苦、文本写了几成或项目完成了多少，而应描述：**指定文档版本，在指定判据和用途下，目前能否被指定消费者当作可用交付依据。** 它们是文档判定，不是全项目状态机。

| 判定 | 必要语义 | 明确不表示 | 最关键的边界 |
| --- | --- | --- | --- |
| **通过** | 当前版本在声明范围内满足该用途的必要可用性要求，已知限制不越过已授权边界 | 不表示绝对正确、所有用途通过、项目通过或未来修改仍有效 | 只授予该版本、该范围、该用途的消费资格 |
| **部分通过** | 判定集合中有明确部分成立，另有明确部分未成立或尚未成立；通过与未通过边界可指出 | 不表示整体基本通过，也不自动表示未通过部分很小 | “部分判定成立”与“产物可拆出安全可用的部分”是两回事；不可拆时不能按部分通过消费 |
| **拒绝** | 已有足够判断，确认当前版本对声明用途存在实质不适格、矛盾或违反必要要求 | 不表示仅仅还没写、尚未提交、暂时缺证据或永久无救 | 拒绝是肯定性的“不适格”判断，未完成或待取证不是同义词 |
| **人工审判** | 继续判定需要人类专有的目标解释、价值取舍、冲突仲裁、例外或风险接受，超出当前裁判权限 | 不表示一般排队、验收者没空、普通证据缺失或 agent 不愿负责 | 它描述裁决权路由，不是质量结论，也不能借长期挂起形成隐性通过 |
| **待判定** | 尚未形成有效判定，可能因未开始、判定进行中、必要证据不足或客观判定点尚未出现 | 不表示通过、部分通过、拒绝，也不必然需要人类价值裁决 | 它描述认识或程序上的未定；若根因是规范冲突，才进入人工审判 |

### 4.2 五态并非天然同一本体，不能假装它们已经完全自洽

【确定】通过、部分通过、拒绝接近判定结果；待判定接近认识或程序状态；人工审判接近权限路由。把这五个词放在同一组里，会产生结构性混用风险。本文不另造具体处理策略，但必须指出：**若保留五态，就不能让它独自承担全部控制语义；至少要能下钻看到判定对象、版本、用途、证据状态、所需权威和未决范围。**

“人工审判”和“待判定”的区别不能由等待时间长短决定。【确定】证据不足但判据清楚，是待判定；证据齐全但需要决定相互冲突的价值何者优先，是人工审判。若既缺证据又有规范争议，两种事实可以并存，不能为了单一标签而隐去其中之一。

“拒绝”与“尚未完成”的区别也不能由文档外表决定。草稿可能尚未完成但并无已知方向错误，完整候选也可能因自相矛盾而被拒绝。【推测】如果把所有未完成都标成拒绝，执行者会倾向于延迟提交、隐藏早期不确定性；如果把所有拒绝都软化成待判定，又会掩盖已经确定的不适格。

### 4.3 部分通过最容易制造授权幻觉

【确定】部分通过不是一个可与完成度互换的百分比。目标文档中十条判据有九条可判定，不代表文档“九成可用”；若剩下一条决定整个目标含义，则整体可能无法任务化。反之，一份任务文档中只有可分离的低风险附录未通过，主体仍可能具有明确受限用途。

因此必须保留两项独立事实：**哪些部分已经通过，以及未通过部分是否污染已通过部分的消费。**【存疑】具体项目能否接受受限消费，取决于依赖关系、风险与有权者对范围的接受，不能由“部分通过”四字自动授权。

### 4.4 文档判定与其他四类状态必须分离

| 维度 | 回答的问题 | 典型反例，说明为何不能合并 |
| --- | --- | --- |
| 文档可用性判定 | 某版本能否作为指定用途的依据 | 目标文档可以通过，但计划尚未开始 |
| 任务执行状态 | 工作是否已执行、阻断、提交、自验完毕 | 工作 agent 已标任务完成，但任务文档后来被证明版本失效 |
| 阶段进度 | 当前阶段义务覆盖、依赖闭合和集成推进到何处 | 多数任务已执行完，但跨任务集成尚未形成，阶段不能据此视为完成 |
| 项目可用性 | 实际产物在指定场景下能否支持目标使用 | 阶段任务合规，但真实用户无法完成核心目标，项目仍不可用 |
| 最终完成 | 有权人类是否在目标、偏离、遗留和副作用显式呈现后作出规范闭环 | 产物当前可用，但仍有未接受义务；或人类接受部分遗留完成项目，却不能说偏离为零 |

【确定】工作 agent 的“任务完成”最合理的含义是：**执行活动已结束或达到提交边界，自验已完成，产物、证据、偏差和不确定项已经提交，因而具备接受独立验收的资格。** 它不是独立验收结论，不是阶段进度结论，更不是项目完成。

任务完成可以向阶段验收提供输入，但不能自动向上传播。阶段验收结论可以支持总验收，但不能抵消目标偏离。真实使用可以证明某些场景中的可用性，也不能自动替代人类对遗留义务的接受。

## 5. 工作自验、阶段工作区验收与最终真实使用验收

### 5.1 工作自验：证明提交责任，不证明独立正确

工作自验回答：“我是否按当前任务版本做了被授权的事，是否检查了我知道如何检查的内容，是否如实交出了产物、证据、偏差和未知？”其证据主要包括实际产物、执行结果、已知限制和偏差说明。

【确定】工作 agent 有权宣布“我已履行提交责任”，无权宣布“我的产物已独立通过”。即使其自验采用与验收 agent 完全相同的检查，二者仍不重复：前者是作者对自身执行完整性的负责，后者是对作者主张的独立质疑。

【推测】若独立验收只是机械重跑工作自验，它确实会成为重复劳动；真正有价值的独立验收应检查自验是否问对了问题、证据是否可信、任务之间是否发生不良组合，而不是只复制作者的测试叙述。

### 5.2 文档可用性检查：审“能否据此行动”，不是再审一遍作者态度

目标文档和开发任务文档都需要可用性检查，但两者权威来源不同。目标文档的规范含义由人类确认，独立检查关注歧义、判据可判定性、非目标、授权边界和消费者能否理解；开发任务文档则对照有效目标，检查分解是否遗漏、是否擅改义务、依赖和集成是否清楚、工作 agent 是否需要重建大量隐藏推理。

【推测】让计划 agent 对目标文档提出“陌生消费者异议”有价值，因为它能暴露解释负债；但若让计划 agent 单独批准目标文档，又可能诱使它选择最容易分解的解释。因此下游可读性意见应是证据，不应自动成为规范批准。

### 5.3 阶段工作区验收：五个不可缺的问题

阶段验收必须直接依据有效目标文档，并触及原始目标和目标沿革，而不是只读开发任务文档、执行汇报或主 agent 摘要。它至少要回答：

1. **局部义务**：本阶段承诺的目标义务是否有实际产物和证据支持，而非只有任务完成标记？
2. **跨任务集成**：分别成立的产物组合后是否仍成立，是否出现接口语义、优先级、资源或行为上的组合冲突？
3. **目标轨迹**：当前成果是在接近目标，还是仅以高完成度远离目标？是否借计划分解改变了非目标和价值排序？
4. **当前可用性**：在阶段声明的场景中，项目是否已有可使用能力，还是只有不可组合的功能碎片？
5. **剩余风险**：有哪些未决争议、偏差、副作用、临时处置、证据缺口和可能向后传播的风险？

【确定】任务文档只能提供“计划声称要做什么”，目标文档才提供“为何这些义务值得完成”。所以只验收任务清单，会把计划错误和执行正确组合成一个稳定的全绿错误系统。

【推测】阶段全过还会产生锚定：后续验收者倾向于维护先前判断，团队倾向于因沉没成本而拒绝回退。因此阶段结论必须是可受新集成证据挑战的历史判断，不是永久免审区。

### 5.4 “验收 agent 联合人类”的合理分工

【确定】验收 agent 与人类应联合的是互补判断，而不是重复签字。验收 agent 负责事实、证据、合规、集成和偏离报告；人类负责目标含义、价值冲突、重大例外、其权限内的遗留接受和是否继续投入。

对于没有规范争议、没有越权、没有不可逆后果的常规阶段，人类预先批准的目标和授权已经参与该阶段，未必要再签一次“我同意验收 agent 看到的事实”。对于目标轨迹偏移、部分范围接受、价值冲突或重大遗留，人类必须实际裁决。**【推测】把所有阶段都变成强制人签，不会线性提高安全性，反而可能降低最终关键裁决的质量。**

### 5.5 最终真实使用：与演示、测试和文档审查的差别

- **演示**证明在选定路径和叙述下可以展示某些行为；演示者可以避开失败路径。
- **测试通过**证明在既定检查条件下某些判据被满足；判据可能漏掉价值、集成或真实变化。
- **文档审查**证明文字和证据叙述具有某种一致性；它不能单独证明实际产物可用。
- **真实使用**则要求使用行为服务于真实目标，由实际目标用户或有合法代表性的使用者，以真实需求而非帮助开发者过关为目的，面对使用中自然出现的判断和变化。

【确定】如果工作 agent 只是按预设脚本替用户操作，那通常仍是演示，不是真实使用；除非该工作 agent 本身就是目标用户，并在为自己的真实需要使用产物。用户是否“真实”不由操作者身份单独决定，而由使用目的是否独立于“帮项目通过”决定。

在工作区进行真实使用，能够证明的是：**该项目版本在这些真实使用情境中，曾支持或未能支持相应目标，并暴露出某些集成、价值、可用性和副作用问题。** 它不能自动证明所有用户、所有环境、长期效果、潜伏期副作用、未观察风险或未来版本。

【存疑】若目标本身要求工作区之外的实际部署、真实第三方参与或长周期反馈，工作区内使用只能提供有限证据。此时不能把工作区验收包装成完整外部验收；只能等待外部证据、明确限制完成主张，或由有权人类显式接受未知，而不是宣称未知不存在。

### 5.6 真实使用与总验收不应成为两道重复门

【确定】真实使用是总验收中的证据生成与价值检验核心，总验收则把该证据与目标义务、跨阶段集成、非目标、副作用、遗留和争议合并判断。二者功能不同但不必重复走两套完整流程。

最终完成权属于有权人类，但“有权”不仅是项目内部指定的目标所有者。若遗留风险会转嫁给未授权第三方，该目标所有者未必有权替他们接受。【存疑】谁是合法接受者、是否需要其他利益相关者参与，是权责框架本身无法自行解决的治理问题。

### 5.7 验收独立性的实际上限

验收独立性至少包含作者分离、证据直达、无过关利益绑定、裁判权限分离和异源挑战。换一个 agent 名字只实现最浅的一层。

【确定】同模型、同前提、同摘要来源的验收只能形成程序性独立，不能保证认识论独立。真实使用、人类判断和异源异议可以提供不同信号，但它们也会犯错，不能被神化为真理机器。

【推测】让同一验收 agent 贯穿所有阶段有连续性收益，也有固化解释的风险。较合理的制衡不是无限增加验收角色，而是确保其不能直接修改受验对象、最终人类看到未决异议、真实使用不由执行者代演，并在高风险或重大争议时引入不共享作者立场的挑战。

## 6. 主 agent 隐性代决与人类裁决预算

### 6.1 主 agent 不点击“批准”，也可能实际作出全部关键决定

【确定】主 agent 的隐性代决至少有以下七条路径：

1. **翻译代决**：把人类的模糊目标写成唯一解释，把其他合理解释从目标文档中消失。
2. **选项代决**：只提供自己和某个明显荒谬选项，引导人类“选择”预定答案。
3. **摘要代决**：省略异议、失败证据、被否决路径和适用范围，使人类在压缩信息上签字。
4. **分诊代决**：决定哪些问题“不需要打扰人类”，从而在路由阶段行使了实际规范权。
5. **默认代决**：把沉默、超时或预算不足解释为同意，或者设置倾向通过的默认选项。
6. **状态代决**：用“基本完成”“原则上可用”“仅剩小问题”等措辞，把待判定、部分通过与人工审判改写为事实通过。
7. **节奏代决**：通过紧急化、拆分或捆绑裁决，使人类没有足够时间理解真正取舍。

因此，“主 agent 协调而非代决”不能只靠角色宣言。其提交给人类的材料应使人类看见：待裁的精确问题、合理选项及其后果、维持现状或停止的选项、被否决方案及理由、未收敛异议、事实与假设的区分、可逆性和授权范围。主 agent 的推荐可以存在，但必须与证据和其他选项分离。

【推测】这些要求仍不能根除代决，因为“哪些是合理选项”“哪些异议重要”仍可能由主 agent 判断。额外的必要制衡是：人类和独立验收者有权直达原始材料、重开已归类事项，而不是只能在主 agent 提供的摘要内选择。

### 6.2 人类裁决预算不是签字数量，而是五种稀缺资源

人类预算至少包括注意力、理解上下文的时间、相关能力、裁决时效和合法责任承担能力。【确定】门禁数量增加并不自动增加有效控制；同一人类在同一背景下重复确认同一事实，消耗预算却不增加独立性。

【推测】当裁决密度超过预算，常见退化不是立即停工，而是签字形式化：依赖主 agent 推荐、只看红绿灯、默认通过、把争议推迟到人工审判停车场。最终系统看起来门禁齐全，实际只剩代理人的判断。

### 6.3 应按决策性质分配人类预算

| 决策类型 | 合适的权威 | 理由 |
| --- | --- | --- |
| 新目标、非目标、价值排序、重大成功判据、风险偏好的确定或实质变化 | 有权人类 | 属于规范选择，不能由事实多数或 agent 能力替代 |
| 超授权、不可逆、高外溢风险行动，以及重大遗留接受 | 有权人类，必要时包括受影响方权威 | 改变他人义务或风险承担 |
| 最终项目完成、元规则、模型／角色权限／验收独立性与控制流的进化 | 有权人类 | 涉及最终责任和“谁有权改规则” |
| 既有授权内的客观证据核验、版本一致性、文档可读性、常规集成判断 | 独立验收 agent，人类处理异议 | 属于可质疑的事实判定，不必重复人签 |
| 既定任务内的局部、可逆执行选择 | 计划或工作 agent，依层级而定 | 属于执行授权，过度人裁只会制造瓶颈 |
| 未决假设下的低风险探索 | 可在明确预授权内由 agent 开展 | 探索用于消除不确定性，不应被包装成人类已批准事实 |

预授权必须能说明适用对象、范围、条件、风险与成本边界、有效条件、撤销和升级触发点。【确定】预授权不是空白支票，授权人类也没有因此免除最终责任；授权到期或目标失效时，不能把沉默当续期。

### 6.4 合并裁决应合并“共同根因”，不是捆绑无关事项

多个任务若都依赖同一个价值取舍，可以由一次清楚的人类裁决覆盖，避免重复提问。无关事项不应为了省一次签字被捆成总包，否则人类很难知道自己在批准什么。

【确定】当人类预算耗尽或合法权威缺席时，合法结果是待判定、缩小范围、暂停或终止，而不是由 agent 代为批准。**预算不足是停止扩权的理由，不是降低权威的借口。**

## 7. 全量验收、开发期学习冻结与验收后进化

### 7.1 全量验收的最低含义

【确定】全量验收既不是所有历史任务都绿，也不是所有文档都曾通过，更不是工作 agent 完成标记的总和。其最低含义应包括：

1. 原目标、现行有效目标和目标沿革均可辨认，项目义务以有效目标为准，同时保留对原承诺的偏离说明。
2. 所有仍有效的目标义务均已闭合，或其未闭合部分被明确呈现并由有权人类接受；被合法废止的旧任务不必为了形式全绿而重做。
3. 阶段与跨阶段集成证据足以支持整体判断，且阶段结论没有遮蔽后来出现的失效。
4. 已按目标完成真实使用验收，或已明确说明真实使用证据的边界，不能把演示冒充真实使用。
5. 非目标、重大副作用、未决异议、偏差和遗留均已呈报；不存在被隐藏的关键人工审判或实质待判定事项。
6. 完成度与偏离度分别报告，不以高完成抵消高偏离，也不以人类接受遗留反推“从未偏离”。
7. 有权人类基于上述证据作出完成决定，并冻结对应项目基线；该决定只覆盖当时版本和声明范围。

全量验收因此是**规范闭环与证据闭环在特定基线上的共同成立**，不是零缺陷或全知。【存疑】当关键真实反馈必须长期等待时，人类可以选择延后完成、作出明确有限的完成决定或接受某些未知；但这三种主张不能混写成“所有效果均已验证”。

### 7.2 为什么要把经验收敛和模型进化放到其后

【推测】这一延迟有三项收益：

- **减少局部过拟合**：单次任务偏差不会立刻变成跨项目规则。
- **保护验收基线**：开发中不持续改变模型、技能和控制流，验收对象的认知与控制条件更稳定。
- **利用结果证据归因**：看到集成和真实使用结果后，较容易区分执行缺陷、计划缺陷、目标缺陷与真正的可复用教训。

【确定】这些收益只有在“延迟泛化”而非“延迟记录和纠错”时才成立。如果把冻结学习理解为开发中不得修改错误做法，就会让项目明知错误仍持续执行。

### 7.3 开发期必须保留与必须延后的行为

| 开发期仍可且应当发生 | 开发期原则上延后到全量验收后 |
| --- | --- |
| 显性记录已发现的错误、偏差、阻断、证据缺口与上下文 | 从单次或当前项目错误直接泛化出跨任务规则 |
| 局部返工、补证据、修复执行、回计划或回目标重订 | 将局部教训晋升为长期约束、普遍判例或组织价值 |
| 阻断、停止、止损、收缩权限、恢复到已批准安全基线 | 技能化、长期记忆改写、模型进化和控制流进化 |
| 为当前任务设置可撤销、适用边界清楚的临时约束 | 以“纠错”为名永久改变角色权限、否决门或人类门禁 |
| 保存争议、反例、失败路径、已试修复和现场上下文，去重并标记冲突 | 在未审查归因和反例前宣布“系统已经学会” |

安全处置是收缩性例外：可以停止危险行为、撤销扩权、退回已批准基线，不能借紧急之名扩大权限或削弱否决点。【存疑】若防止即时伤害确实需要新增普遍性控制，其紧急权限和事后复核边界必须由人类预先授权，不能由本文代为放宽。

### 7.4 字面规则对失败项目存在逻辑缺口

【确定】若经验收敛只能在“全量验收完成后”发生，那么中止、失败或永远无法完成真实使用的项目将永远没有合法学习时点。这不仅损失失败教训，还会制造把项目勉强宣布为全量验收以解锁学习的激励。

本文建议作一项明确修正：**成功项目在全量验收并冻结基线后学习；失败或中止项目在正式终止、证据与责任封存后学习，但不得把终止复盘冒充项目验收。** 这与原字面要求存在差异，属于【存疑】的治理选择，需要人类裁决。若坚持原字面规则，就必须承认它主动放弃失败项目的组织学习。

### 7.5 延后学习的代价不能靠一句“先记下来”消解

【推测】开发期冻结泛化至少会带来四种代价：同类错误在不同任务重复发生；临时约束各自演化而互相冲突；观察台账积累到无法归因；现场上下文、反例和被否决路径在末端丢失。

因此，开发期虽然不做经验晋升，却必须做高保真观察和上下文保全。记录应先保留“观察到什么、期望什么、在哪一版本、当时有哪些替代解释”，而不是过早写成唯一根因。去重和冲突标记可以减少噪声，但不能 secretly 把高频当作普遍因果。

### 7.6 验收后的经验收敛与模型进化不是自动生效

合理的概念顺序是：先冻结已验收项目及证据，再对观察记录作独立归因；区分一次性事件、项目特定教训和跨项目候选；允许“证据不足，继续观察”和“明确不沉淀”；最后按影响半径决定谁有权批准经验、技能、长期记忆、模型或控制流变化。

【确定】全量验收是学习启动的必要条件之一，不是学习正确性的充分保证。一个成功项目也可能只是偶然成功，一次被人类接受的遗留也不证明该遗留无害。

### 7.7 变更后的再验证责任

| 验收后变化 | 对原验收结论的影响 | 新的责任 |
| --- | --- | --- |
| 仅形成组织观察或未应用到该项目的候选经验 | 不 retroactively 改写原项目历史验收 | 不得把候选经验当已验证规则，未来采用时重新取证 |
| 修改未来项目使用的技能、记忆或模板 | 原项目仍可作为历史案例，但不能证明新技能或新模板有效 | 对新的适用范围和失败模式承担验证责任 |
| 修改已验收项目产物或其实际运行控制条件 | 原结论只绑定旧版本，变化部分成为新候选 | 评估受影响主张并重新验收，不能沿用同一项目全绿叙述 |
| 改变模型、核心判据、角色权限、人类门禁或关键控制流 | 可能使生成证据和裁判证据同时失效 | 人类批准变更，重新确定受影响验证范围；重大影响时不能只作局部形式复核 |

【推测】最隐蔽的污染不是直接修改产品，而是只改变验收者或主 agent 的摘要与控制逻辑，却继续引用旧验收结果证明新系统可靠。再验证责任因此不仅针对产品行为，也针对产生和解释证据的机制。

## 8. 优异点、缺陷、适用边界与冗余收缩

### 8.1 真正优异点及其成立条件

| 优异点 | 为什么有价值 | 成立的必要条件 |
| --- | --- | --- |
| 文档以可用性而非写完为交付门 | 防止不可理解、不可判定的输入被下游放大 | 判定绑定版本、消费者和用途；作者不能单独自授消费资格 |
| 主 agent 协调、计划任务化、工作执行、独立验收分权 | 把规范、执行和证据判断分开，减少自证 | 主 agent 不控制唯一信息入口；验收者能直达目标和实际工作区 |
| 阶段直接验收工作区与目标轨迹 | 能发现“任务全做但整体偏离”及组合缺陷 | 工作区不是只有自述；阶段验收包含集成、当前可用性和剩余风险 |
| 自验、阶段验收、总验收分层 | 分别覆盖提交责任、阶段消费资格和项目价值闭环 | 各层不重复复制同一检查，也不互相冒充最终权限 |
| 真实使用进入最终验收 | 提供不同于作者与测试脚本的外部信号 | 使用目的真实，非执行者代演；目标用户和使用边界有代表性 |
| 全量验收后才泛化学习 | 降低开发期局部过拟合，保护已验基线 | 观察、局部纠错与安全处置不冻结；学习后变更有独立授权和再验证 |
| 人类裁决预算显式化 | 把有限注意力用于真正规范和高风险问题 | 有清楚预授权、例外升级和预算耗尽时的停止规则 |
| 工作区承接版本、证据和否决历史 | 支持接手、审计与证迹复现，减少对话接力损失 | 工作区记录能与实际产物对照，且不会把记录自洽当成现实正确 |

【推测】这些优点共同成立时，框架最大的收益不是“自动化更多”，而是**减少未经授权的意义变化，并使每项完成主张都能被限制在其实际证据范围内。**

### 8.2 结构性缺陷

1. **认知共同盲区不会因角色数量消失。**【确定】主、计划、工作和验收可以共享同一错误目标理解，真实用户也可能只覆盖有限情境。
2. **文档门可能转向可执行性表演。**【推测】为了获得通过，计划者会优先选择容易写、容易测、容易分工的目标，而不是重要目标。
3. **多版本、多维度状态增加理解负担。**【推测】若操作者只看最上方标签，再精细的内部语义也无法阻止部分通过被当整体通过。
4. **直接验收工作区仍可能被布置。**【推测】工作区可以只保留成功证据和理想使用环境，独立验收若不接触反例和真实使用，只会更深入地确认同一叙述。
5. **延后学习会用重复错误换取基线稳定。**【推测】长项目、强耦合项目和高频相似任务付出的代价尤其大。
6. **人类最终权威不等于人类最终正确。**【确定】权威解决“谁负责决定”，不解决“事实是否充分、价值是否正当”；若人类缺能力或存在利益冲突，流程无法自我修复。
7. **真实使用可能迟缓、昂贵或不宜在项目工作区发生。**【存疑】对这些项目，最终验收要么长期开放，要么只能给出有限完成主张。
8. **严格权责分离会降低速度并可能抑制探索。**【推测】当目标本身通过实践才逐渐清晰时，过早钉版会把学习需求误判为目标偏离。

### 8.3 必要制衡与可删除冗余

核心原则是：**功能不可因合并仪式而消失，仪式不可因功能重要而无限复制。**

| 看似重复的环节 | 必要制衡在哪里 | 可删除或合并的冗余 | 简化边界 |
| --- | --- | --- | --- |
| 主 agent 与验收 agent | 主 agent 参与目标草拟、选项和状态构造；独立验收防止作者自证 | 不必让两者重复撰写完整项目叙述；验收可直接引用证据并只报告差量与异议 | 主 agent 未参与内容且项目极低风险时，可由独立人类真实使用承担检查，不必形式化双角色 |
| 目标文档与开发任务文档 | 前者承载为何与义务，后者承载如何与分工；计划不得借改写任务改变目标 | 不必逐字复制目标背景，不必为每个微小动作各建一套审批文书 | 单阶段、少任务项目可合一文档，但仍须能区分目标权与计划权 |
| 文档可用性验收与阶段产物验收 | 前者审“依据能否消费”，后者审“实际产物是否实现目标” | 不必在阶段验收重新评审未变化文档的全部文字 | 若文档变更影响阶段判据或目标绑定，则必须重新检查受影响部分 |
| 工作自验与独立验收 | 自验证明作者履行提交责任，独立验收挑战作者盲区 | 独立验收不必机械重述作者已提供的可复现事实 | 高风险、强价值或跨任务成果不能因自验详尽而取消独立性 |
| 阶段验收与总验收 | 阶段控制后续消费和早期纠偏，总验收控制整体目标、真实使用、遗留和完成 | 总验收可复用仍有效的阶段证据，不应无条件全量重验 | 单阶段项目可合并仪式，但局部集成、真实使用、最终人裁的问题仍要全部回答 |
| 真实使用与总验收 | 真实使用生成外部使用信号，总验收作目标与责任闭环 | 不必先“真实使用签字”再“总验收签字”走两套完整文书 | 真实使用不能被总验收文档审查替代 |
| 人类在目标、阶段、总验收多处参与 | 人类保有规范、价值和最终责任 | 删除对未变化事实的重复签字、重复确认相同证据、重复批准同一根取舍 | 新目标／重大判据、越权、重大遗留、最终完成和元变更不可由精简转交 agent |
| 多 agent 或异构复核 | 提供不同质疑路径，可能暴露共同前提 | 删除只读同一摘要、只改写同一结论的“第二意见” | 异源意见也不是批准权；是否值得引入取决于风险和证据增益 |

### 8.4 可以明确收缩的框架规模

- **完整框架**：适合多阶段、多 agent、跨会话、目标可分解且较稳定、真实使用可行、失败或返工成本高、需要审计和接手的项目。
- **轻量框架**：适合短、低风险、可逆、单阶段项目。可合并目标与任务文档、取消独立阶段仪式、让最终人类真实使用直接承担独立检查；但不能删除目标责任、版本所指、自验不等于最终验收、偏离与遗留显式化。
- **不宜机械套用**：目标高度开放、整体审美不可分、反馈远慢于开发、验证成本远高于返工成本、一次性微小任务或强实时处置。此时完整流程可能净收益为负。
- **完整框架仍不充分**：高外溢、高不可逆、涉及多方权益的项目，单靠内部角色制衡不足，合法权威和外部责任问题优先于流程完整度。

【存疑】何时从轻量升级为完整，不应只按项目时长或 agent 数量决定，更应看目标歧义、依赖耦合、失败损失、可逆性、证据成本和人类可用裁决能力。

## 9. 具体失效模式与漏洞

以下严重度是概念上的相对评级：极高表示可能摧毁规范权威、最终验收或造成重大不可逆后果；高表示可能形成系统性假通过或大规模返工；中高表示会明显削弱控制、恢复或学习效率。实际发生概率均为【存疑】，表内机制属于有理由的【推测】，其中涉及语义矛盾的指出为【确定】。

| 编号 | 失效模式 | 触发机制 | 主要后果 | 严重度 | 概念级补偿方向 |
| --- | --- | --- | --- | --- | --- |
| V01 | 主 agent 翻译目标时隐性定权 | 模糊目标被写成唯一可执行解释，其他合理含义未呈报 | 全链高效执行错误目标，人类误以为已批准该解释 | 极高 | 保留合理解释、非目标和未决项；实质价值解释由人类定权，主 agent 只草拟 |
| V02 | 选项与摘要构造替代人类裁决 | 主 agent 控制选项顺序、证据取舍、推荐措辞和失败可见性 | 人类形式选择、agent 实质决策；异议被洗稿 | 极高 | 原始证据直达，保留被否决项和未收敛异议，允许人类重开问题 |
| V03 | 主 agent 通过分诊隐性代决 | 主 agent 将规范争议归类为普通事实或低风险执行，因而不升级 | 再完善的角色表也被路由层绕过 | 极高 | 分诊依据受预授权约束，保留路由理由和独立质疑入口；禁止沉默默认同意 |
| V04 | 计划 agent 为“可用文档”降标 | 将难验证、难分解但重要的目标改成容易执行和验收的任务 | 文档通过变成可执行性表演，价值目标流失 | 极高 | 目标映射与偏离检查；计划只能提出目标重议，不能自行软化义务 |
| V05 | 人类门禁密度导致橡皮图章 | 每阶段、每文档、每任务都重复签字，裁决超过注意力与理解预算 | 后续关键裁决也默认通过，签字不再提供有效控制 | 极高 | 按规范性和风险分配人裁；预授权、例外升级、合并同根决策，预算耗尽则暂停 |
| V06 | 预授权退化为空白支票 | 授权范围、失效条件和升级边界模糊，或长期不复审 | agent 以旧授权处理新目标、新风险，责任名义在人、实际控制无人负责 | 高 | 限定对象、范围、风险、有效条件和撤销；目标或环境实质变化即重审授权 |
| V07 | 合法权威与真实利益相关者错位 | 目标所有者接受的风险实际由第三方承担，或其本身存在过关利益 | 项目内部“完成”却外部不正义或不可接受，遗留接受无效 | 极高 | 明确谁有权接受何种遗留；外溢风险需相应受影响方或合法权威参与 |
| V08 | 五态混合结果、证据和路由 | 人工审判被当质量判定，待判定被当拒绝或即将通过 | 消费资格不清，人工审判成为永久停车场，责任被拖延掩盖 | 高 | 五态只作文档判定表达，保留下钻的版本、用途、证据和所需权威事实 |
| V09 | 部分通过被当作整体通过 | 摘要只显示“通过部分”，下游忽略未通过项及其依赖 | 未验证目标或任务进入执行，缺陷沿主链放大 | 高 | 明确通过范围、未通过范围和依赖污染；受限消费不能由标签自动推出 |
| V10 | 旧版本通过被新修改继承 | 文档或目标原地变化，状态仍显示通过；在途任务继续引用旧结论 | 验收对象变形，旧证据为新内容背书 | 高 | 判定绑定版本与用途；变化后检查失效和重新绑定，不原地继承消费资格 |
| V11 | 拒绝与尚未完成混用 | 缺证据被视为确定不适格，或已确定不适格被软化为待判定 | 前者激励隐瞒和延迟提交，后者让已知缺陷长期滞留 | 中高 | 区分肯定性缺陷判断与证据／程序未定，保留真实不确定性和明确缺陷理由 |
| V12 | 文档可用性变成文书表演 | 评审只看格式齐全、术语一致和清单完整，不测试消费者能否正确行动 | 文档漂亮但解释负债巨大，下游各自重建不同目标 | 高 | 以指定消费者的理解和决策一致性为证据，保留否决记录与实际歧义 |
| V13 | 工作完成标记逐级滚成项目完成 | 任务完成被汇总为阶段完成，阶段完成再被汇总为最终完成 | 自验同源缺陷与集成缺陷被封存，项目全绿但不可用 | 极高 | 各层主张分别授权；任务完成只取得提交资格，最终完成必须经独立总验收和人裁 |
| V14 | 验收只读汇报或把工作区自述当事实 | 验收者不接触实际产物、失败证据和真实使用，只复核主 agent 摘要 | 高质量假象获得“独立验收”背书 | 极高 | 直接读取目标和工作区实际对象；区分自述、可复现证据与真实使用信号 |
| V15 | 验收者修复后继续担任同版独立裁判 | 为赶进度，验收 agent 直接改产物或判据，再宣布通过 | 作者与裁判重新合一，利益冲突和盲区被封存 | 高 | 修复交回执行角色；参与修复即披露独立性损失，并重新取得独立判断 |
| V16 | 同模型与同前提形成共同盲区 | 主、计划、工作、验收共享错误假设，四席复核又共享材料 | 多方一致反而提高错误置信度，真正前提无人质疑 | 高 | 承认可认识上限；引入真实使用、合法人类判断和不只读摘要的异源异议 |
| V17 | 阶段验收只做局部任务合规 | 各任务按清单通过，但不检查跨任务交互和整体使用 | 组合后失效，局部越严格越掩盖整体缺陷 | 极高 | 阶段必须含跨任务集成、目标轨迹、当前可用性和剩余风险 |
| V18 | 先前阶段通过造成锚定和沉没成本锁死 | 后续人员不愿推翻已签阶段，新增集成证据被解释为局部例外 | 明显偏离仍继续堆任务，最终只能大规模返工或强行验收 | 高 | 阶段结论限定版本和范围，新证据可挑战；保留回计划、回目标的合法出口 |
| V19 | 真实使用被脚本演示或执行者代演 | 只走理想路径，用户为配合过关而操作，或工作 agent 替用户完成 | 演示结果被当作价值与可用性证据 | 极高 | 使用目的独立、路径允许真实变化；报告使用者、情境和未覆盖范围 |
| V20 | 工作区真实使用被过度外推 | 受控工作区覆盖不了真实外部环境、第三方、长期副作用 | 局部使用成功被误称完整外部验收，延迟风险在完成后暴露 | 高 | 限定结论外推范围；关键外部反馈未到时等待、限制完成或显式接受未知 |
| V21 | 事后改目标或接受遗留以抹平偏离 | 总验收前重写目标，只按现行目标计算成功；人类签字后被记作“无偏离” | 原承诺失败被洗成成功，经验台账学到错误归因 | 极高 | 原目标、现行目标和沿革并列；完成度与偏离度双报，接受遗留不等于否认偏离 |
| V22 | “所有任务／阶段通过”冒充全量验收 | 忽略非任务义务、真实使用、副作用、未决异议和合法废止任务 | 一方面假完成，另一方面为形式全绿重做无效旧任务 | 高 | 以有效目标义务、集成、真实使用、遗留人裁和基线冻结共同定义全量验收 |
| V23 | 开发期冻结泛化导致重复错误和台账失真 | 相同缺陷跨任务重现，观察只增不治理，现场上下文随时间丢失 | 返工增加，末端归因被噪声和记忆缺失主导 | 高 | 允许局部纠错、临时约束、上下文保全、去重和冲突标记；泛化仍延后 |
| V24 | 冻结学习被用于阻止安全处置，或纠错被用于偷渡进化 | 字面禁止一切变化，或以“临时修复”为名永久改控制流和权限 | 前者扩大即时伤害，后者绕开人类元规则权 | 极高 | 允许收缩性停止、止损和回退；长期泛化、扩权和控制流改变仍受审并由人定权 |
| V25 | 验收后进化污染已验基线 | 修改模型、技能、摘要或控制流，却继续引用旧项目全量验收 | 新旧证据错配，变化后的系统借旧信誉运行 | 极高 | 冻结历史基线，区分历史有效与当前有效；按受影响主张承担再验证责任 |
| V26 | 失败项目永远没有学习时点 | 只有全量验收后才能收敛经验，而中止项目永远达不到门槛 | 失败教训流失，并激励为解锁学习而假宣布完成 | 高 | 人类决定是否增加“正式终止并封存证据后学习”的独立出口，且不冒充验收 |
| V27 | 多重角色与重复验收稀释责任 | 每个人都只复核他人摘要，出错后以“上游已签”为由免责 | 成本增加而无人真正对目标、证据和遗留负责 | 高 | 每层指定唯一问题与权限，复用证据、只审差量和新增风险，删除无新增判断的仪式 |
| V28 | 以精简为名删除必要制衡 | 单阶段或短项目合并角色后，作者同时定目标、执行、验收并宣布完成 | 冗余下降但自证和隐性代决重新出现 | 高 | 合并仪式不合并规范与证据责任；至少保留独立最终使用或人类检查及偏离呈报 |
| V29 | 验收 agent 借判据解释取得规范权 | 多种合理解释中，验收者选择最容易判或最符合自身偏好的一种 | 计划或执行者被迫优化裁判偏好，而非人类目标 | 高 | 将改变价值与风险分配的解释分歧提交人工审判；事实判定与规范解释分开报告 |
| V30 | 成功项目和已接受遗留被误当学习真因 | 从一次成功直接提炼规则，或把人类接受风险当成风险不存在 | 迷信和偏见被技能化，后续项目放大错误 | 高 | 独立归因、保留反例与“不沉淀”出口；全量验收只允许开始分析，不保证经验为真 |

## 10. 最值得保留的最低控制基线

若必须大幅压缩整套构想，本文建议保留以下九项。它们保留的是控制功能，不要求每项都成为独立会议、独立文档或独立签字。

1. **人类规范权威**：原目标、现行目标、非目标、重大判据、授权边界和最终责任可辨认；实质变化由有权人类决定，沿革不得抹除。
2. **主 agent 不代决**：其草拟、汇总和分诊必须保留合理选项、否决、异议、事实与假设之分；人类和验收者能直达原始材料，沉默不构成批准。
3. **计划不扩权**：任务化只在有效目标与授权内发生，不能为可执行而降低目标；计划和目标缺陷有各自回退出口。
4. **版本化有限消费**：目标文档、任务文档和项目产物的判定或提交均绑定版本、范围与用途；旧通过不自动覆盖新修改，部分通过不自动成为整体可用。
5. **完成主张分层**：文档通过、任务执行完成、阶段进度、项目当前可用和最终完成分别表达；工作自验只产生提交资格，不产生独立验收或最终完成。
6. **独立且直达证据的验收**：验收不是只读摘要，必须依据目标检查实际工作区；多阶段项目必须有集成、目标轨迹、当前可用性和剩余风险判断。验收者不得修完同版再自任独立裁判。
7. **真实使用与最终人裁**：总验收以目标为根据，以真实使用为核心证据之一，完成度和偏离度不得互抵；遗留由真正有权者显式接受，最终完成不委托给执行或验收 agent。
8. **纠错与学习分离**：开发期持续观察、局部返工、阻断、止损和上下文保全；跨任务泛化、技能化、长期记忆、模型与控制流进化原则上在全量验收后受审。失败项目是否另设终止后学习出口需人类定稿。
9. **进化后再验证与人类预算**：验收后变更不得无成本继承旧证据，影响已验主张或控制机制时产生新的验证责任；人类签字按规范性与风险分配，预算耗尽时停止扩权而非自动通过。

在这九项之内，仍有大量形式可精简：一个文档可以承载目标与计划两节，一次人类裁决可以覆盖同根的多项争议，总验收可以复用有效阶段证据，真实使用与总验收可以同场完成。**最低基线反对的是无新增判断的重复劳动，不反对对作者权力和最终责任的必要制衡。**

## 11. 自我反驳：本框架最可能在哪里失效

### 11.1 “事实判定／规范决定”本身无法干净切开

【确定】本文把人类预算建立在“事实由 agent 核验、规范由人决定”之上，但实际判据解释、证据充分性、风险严重度往往同时包含事实与价值。主 agent 或验收 agent 仍可通过归类来行使隐性规范权。保留异议和直达原始材料只能降低风险，不能提供客观无争议的分类器。若人类把每次分类争议都收回，裁决预算又会再次爆炸。

### 11.2 反隐性代决措施可能制造更多由主 agent 控制的文本

【推测】要求保留所有选项、反例、否决和证据，可能使决策材料膨胀，最终人类仍只读主 agent 新写的“摘要的摘要”。这意味着本文的解决方案存在自反性：为防止摘要代决而增加记录，记录过多又迫使人类依赖摘要。真正有效的可能是更少而非更多的关键裁决，但“更少”如何不变成少报，仍属【存疑】。

### 11.3 独立验收与真实使用仍可能共同验证错误目标

【确定】如果目标文档本身错误、工作区被选择性布置、真实用户只覆盖窄场景，那么自验、阶段验收、真实使用和总验收可以在各自层面都诚实工作，却仍共同得出有害或不适用的完成结论。本文的框架主要防止无权推断和证据错配，不能保证目标正当，也不能保证外部效度。

### 11.4 延后学习可能是错误的时间交换

【推测】本文总体上支持先验收后泛化，但在长项目、重复性错误或高安全风险项目中，等待全量验收的成本可能大于局部规则提前收紧的收益。允许“临时约束”虽能缓解，却会引出临时与长期的语义博弈：一个贯穿整个项目的临时约束，实质上已是开发期规则进化。本文无法给出不依赖情境的统一界线，具体边界是【存疑】。

### 11.5 为失败项目增加学习出口也可能被策略性利用

【推测】本文建议失败或中止项目在正式终止后学习，以避免永不学习；但团队可能通过宣布终止来绕过全量验收，再把未经验证的教训晋升为规则。因此该出口必须与“不得宣称项目验收”和严格归因复核绑定。即使如此，它仍削弱了原规则简单明确的防提前学习作用。

### 11.6 版本与再验证责任可能造成永久冻结

【推测】如果任何模型、记忆、技能或控制流变化都被认为可能影响旧证据，系统会陷入持续重验，进化成本无限上升；如果影响范围由主 agent 或验收 agent 自行评估，又可能通过低估影响规避重验。本文提出按受影响主张再验证，却没有也不可能证明影响分析本身可靠。哪些变化必须全量重验，是【存疑】的高风险人裁问题。

### 11.7 精简与制衡之间没有稳定的最优点

【确定】合并目标与任务文档、阶段与总验收、真实使用与总验收，虽然不必然丢失功能，却会让同一参与者更容易在一次语境中压缩问题、淡化异议。本文主张“功能保留、仪式合并”，但实际压力会先删除不易观察的功能，保留容易展示的标签。轻量框架是否仍能维持独立性质疑，必须由真实项目检验，不能靠定义保证。

### 11.8 人类预算框架可能把不负责任合法化

【推测】以“节省人类裁决预算”为名，组织可能把越来越多高风险事项划进预授权，最后只剩最终签字，让人类承担责任而没有实际决策机会。人类最终权威若只是责任兜底，就不是有效制衡。预算应服务更好的判断，而不是服务更少的人类参与；两者的边界属于【存疑】的治理选择。

### 11.9 本框架可能整体上不值得采用

【存疑】若项目很短、可逆、目标通过使用快速澄清，且执行者能力强于判据作者，完整框架的文档、版本、独立验收和延迟学习可能使结果更差。本文能够说明何时应降级，却无法从三份材料证明框架在一般项目上的净收益。它是一种风险控制构想，不是已被证明的通用最佳实践。

## 12. 最需要人类裁决的问题

1. **谁是合法目标所有者、最终完成权威和遗留接受者？** 尤其当副作用影响未参与项目的第三方时，谁有权接受何种风险？
2. **主 agent 的预授权边界是什么？** 哪些目标澄清可视为授权内操作化，哪些解释因改变价值、义务或风险而必须回到人类？主 agent 的分诊由谁复核？
3. **“验收 agent 联合人类进行阶段验收”是否要求每阶段实际人签？** 本文建议常规事实验收不重复人签，规范争议、重大例外和遗留才强制人裁，需确认这是否符合原意。
4. **目标文档与开发任务文档分别由谁授予消费资格？** 人类负责规范确认之外，独立可用性检查应落实到什么程度，哪些低风险文档可合并审查？
5. **五态是否只作为文档判定的对外表达，并允许下钻到版本、用途、证据状态和所需权威？** 若只允许一个标签，如何防止人工审判、待判定与部分通过继续混用？
6. **部分通过在什么条件下能形成受限消费资格？** 谁判断未通过部分是否污染已通过部分，谁有权接受受限范围？
7. **真实使用必须达到何种真实性与覆盖范围？** 当目标指向工作区外部、真实反馈迟缓或真实使用不宜发生时，应等待、有限完成还是显式接受未知？
8. **是否接受“成功项目在全量验收后学习，失败／中止项目在正式终止并封存证据后学习”的修正？** 若不接受，是否明确放弃失败项目的经验收敛？
9. **开发期临时约束与安全处置的边界是什么？** 哪些收缩性处置可立即执行，哪些长期规则、模型或控制流变化无论如何都必须等待并人裁？
10. **验收后各类变化的再验证责任如何划分？** 谁评估影响范围，哪些模型、技能、记忆或控制流变化只需影响验证，哪些必须重新进行全量验收？
11. **人类裁决预算的实际约束与耗尽策略是什么？** 哪些事项可预授权，哪些必须始终保留人类实质判断；预算不足时是缩小范围、延期还是终止，而绝不默认通过？
12. **轻量项目的简化阈值和不可合并项是什么？** 单阶段、短周期、低风险项目可以省略哪些仪式，又如何保证至少存在独立于执行者的真实使用或人类最终检查？
13. **同模型验收的独立性被接受到什么程度？** 哪些高风险情形必须增加不共享摘要的异源异议或额外人类判断，异议与验收结论冲突时由谁裁决？
