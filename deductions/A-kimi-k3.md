# 席位 A 推演：Agent 工程控制工作流

> **元信息**：推演者＝席位 A（独立推演者）；模型＝kimi-k3；推理强度＝最大推理强度（先建模 → 自我反驳 → 收敛）；时间＝2026-11-02 20:17（Asia/Shanghai）；输入依据＝《BRIEF.md》一份（未读取 deductions/ 下其他推演者文件，未使用外部资料）。

## 0. 收敛后的总判断

【推测】七要点本质是面向 agent 的 PDCA 控制环，其创新不在任一环节，而在两处：**以工作区工件取代对话上下文作协作媒介**，以及**把"进化"（错误沉淀＋技能化）设为一等公民**。前者使工程可恢复、可并行、可审计；后者使经验成为项目资产。但有三处承重缺口：验收标准的可信度、进化环的质量控制、工作区的一致性语义——任一失守，全链从工程控制退化为自动化错觉。

## 1. 我的工作流模型

### 1.1 阶段、工件与角色

| 阶段 | 名称 | 角色 | 阶段间工件 |
|---|---|---|---|
| P1 | 目标订立（讨论） | 委托人⇄主控 | **目标宪章**：目标、价值判据（什么算好）、非目标、授权边界 |
| P2 | 方案与任务规划 | 主控/规划者 | **方案书＋任务图**：任务契约（目标、输入指针、验收标准、影响面）＋依赖 |
| P3 | 派发与执行 | 执行子代理 | **工作产物＋决策日志**（岔路选择及理由，落工作区） |
| P4 | 逐条验收 | 验收者（与执行上下文隔离） | **验收记录**：标准逐条→通过/失败→证据指针→缺陷清单 |
| P5 | 错误集收·归因·沉淀 | 主控＋档案员 | **错误条目**（症状、归因、修复、预防规则候选）＋按归因路由的反馈 |
| P6 | 技能化 | 档案员/主控 | **技能**：触发条件＋程序＋自验证，反哺 P2/P3/P4 |
| P7 | 记忆分级（横切基底） | 档案员 | L0 全局元知识 / L1 工程总记忆 / L2 区域记忆（开发、验收、收敛） |

P7 不是第七阶段，而是各阶段读写的持久层。角色是逻辑身份：小工程一人可兼多职，但**执行与验收必须上下文隔离**。

### 1.2 门禁（Gate）

- **G1 目标可判**：价值判据可证伪、范围有界，讨论有收敛判据，否则 P1 不终止。
- **G2 契约完备**：验收标准可独立核对；任务粒度适配执行者能力；依赖无未管理环路。
- **G3 输入可解析**：任务输入全凭工作区解析，不依赖对话记忆。
- **G4 逐条闭环**：标准全过，或缺陷全部登记分流。
- **G5 归因复核**：预防规则晋升前须独立复核——进化环的自质量门，【确定】原构想缺失。
- **G6 技能验证**：复现次数达标且技能本身通过验证方准入库。

### 1.3 任务状态机

`草稿→就绪(G2/G3)→执行中(认领/租约)→已交付→验收中→通过→归档`；旁路：`打回`（携缺陷清单回执行）、`阻塞`（升级主控）、`挂起`（仅凭工作区可恢复）、`失效`（目标/方案变更作废）、`中止`。【确定】约束 2/3 成立的前提：状态机可**从工作区推导**，不存在于任何代理的上下文里。

## 2. 七要点的串联回路

```
              F5:目标类归因(修订宪章)
    ┌────────────────────────────────────────────┐
    ▼                                            │
[P1 目标订立]═目标宪章═>[P2 规划]═方案+任务图═>[P3 派发执行]═产物+决策日志═>[P4 逐条验收]═验收记录═>[交付/归档]
    ▲  ▲                ▲  ▲                 │  ▲                  │缺陷/失败
    │  │F6:技能反哺      │  │F3:粒度/能力回执   │F1:打回重做          ▼
    │  │                │  └─────────────────┘            [P5 错误集收·归因·沉淀]
    │  │                │F2:计划类归因(修订任务图)                   │
    │  │                └────────────────────────────┤F4:验收漏检→修订标准(回P4)
    │  └────────────────────[P6 技能化]<═══规则晋升(G5)═╝
[P7 记忆分级]横切基底：P1–P6 全部读写；中断恢复与新代理接手由此重建上下文(F7)
```

七要点各就各位：1→P1 … 7→P7。**反馈的关键是"先归因、后路由"**：验收失败不直接打回了事，而由 P5 判病因——目标歧义回 P1（F5）、计划缺陷回 P2（F2）、执行能力回 P3（F1/F3）、验收漏检回 P4（F4）；高频元动作经 G5 晋升进 P6 技能化，以程序性记忆注入各环节（F6）。记忆层是唯一同时连接"时间"（恢复）与"人员"（接手）的通道（F7）。

## 3. 概念完整性评估

### 3.1 缺口

【确定】以下机制在七点与约束中均无对应物：

1. **权威与止损**：无授权边界、高风险升级、人类否决点。agent 工程最惨烈的失败是无界行动而非计划不周。
2. **变更管理**：目标中途变更时在途契约如何失效重订？状态机需"失效"态，原构想未提。
3. **验收标准的质量保证**：标准由谁写、如何防盲点继承与指标化？全链质量压在 P2 写出的标准上，而标准无门禁。
4. **合规验收≠价值验收**：逐条验收只验"符合契约"，验不了"适合目的"；契约全过而目标未达需独立的（通常属人的）价值验收。
5. **进化环自质量门（G5）**：归因错误一旦晋升为规则会污染此后所有周期——进化环可能放大错误，而构想未给进化本身设门禁。
6. **生命周期与主控单点**：工程如何收尾、L1 何时经何程序晋升 L0、主控失效如何接管，皆无着落。

### 3.2 伪解耦

【推测】约束宣称"经工作区解耦"，但至少三处是伪解耦：

1. **指派↔验收**：通信解耦了，认知没解耦——验收标准与任务同出规划者之手，盲点同时流入两侧。验收者独立，验收依据不独立。
2. **执行↔工作区**：对话解耦了，状态耦合——工作区是共享可变状态，并发引入脏读、半成品污染、隐性依赖。解耦的是消息，耦合的是状态。
3. **记忆↔全环节**：记忆在时间维度解耦了 agent，在认识维度却耦合——记忆由被它纠正的同一批 agent 书写，新 agent 继承知识也继承扭曲；技能同理，它把"当时的环境"编译进程序，环境漂移后静默失效。时间解耦、认识耦合。

## 4. 失效模式

| # | 失效模式 | 触发条件 | 后果 | 严重度 |
|---|---|---|---|---|
| 1 | 目标幻觉共识 | P1 因迎合偏差过早收敛 | 全链高效执行错误目标 | 高 |
| 2 | 标准代理化(Goodhart) | 标准写成易查代理指标 | 验收全过而价值为零 | 高 |
| 3 | 验收独立性失效 | 验收与规划/执行同源上下文 | 盲点继承，验收成橡皮图章 | 高 |
| 4 | 半成品污染 | 产物无可见性状态被他任务读取 | 错误跨任务传播 | 中高 |
| 5 | 恢复信息缺口 | 关键决策未落工作区 | 恢复后重复或矛盾 | 高 |
| 6 | 假规则沉淀 | 归因浅薄＋G5 缺失 | 进化环注入迷信，污染所有后续周期 | 高 |
| 7 | 记忆膨胀失噪 | 只沉淀不淘汰 | 检索信噪比崩塌 | 中 |
| 8 | 技能腐化 | 环境漂移后未复验 | 自动化地规模化做错 | 高 |
| 9 | 双账漂移 | 同一教训技能/记忆两处存、只改一处 | 指引自相矛盾 | 中 |
| 10 | 变更雪崩 | 目标变更未使在途契约失效 | 验收了已过时交付物 | 中高 |
| 11 | 粒度错配 | 任务超出执行者可靠上下文 | 静默丢需求 | 中高 |
| 12 | 记忆投毒 | 错误/对抗内容写入并晋升 L0 | 跨项目长周期腐蚀 | 高 |
| 13 | 价值验收缺失 | 只验合规无人验适合度 | 交付了没人要的东西 | 中高 |

严重度依据：杀伤力 × 可检测性 × 爆炸半径。6/8/12 单发概率未必最高，但腐蚀的是进化机制本身（持续污染），故判高。

## 5. 优异点与适用边界

**真正的价值**：①工件中心化把协作从"对话接力"变为"工程交接"，恢复、并行、审计由此可能——这是最强一点；②逐条验收把模糊质量变为可枚举检查，并使执行/验收职责分离；③记忆分级＋错误沉淀正面回应 agent 的根本性失忆，经验成为项目资产；④技能化把"每次重新推理"编译为"执行已验证程序"，对稳定模式降本降方差；⑤目标先行拦截 agent 最常见的抢跑失败。

**优点不成立的条件**：【推测】①产出难外化时（品味、架构直觉、探索性研究），工作区留得住结果留不住理由，恢复与验收同时退化；②开放式/创造性目标下"写标准"本身就是难题，工作流只是把困难上移；③沉淀与技能化只在跨任务复现时回本——一次性工程、高新颖领域里教训不迁移，沉淀沦为博物馆；④强耦合系统（全局一致性、架构级不变量）的集成故障落在任务契约缝隙里；⑤模型假设错误皆善意，工作区工件成为注入面的情形在模型之外；⑥低于某复杂度/风险阈值时仪式成本超过失败成本——故需按风险分级的严格度刻度。

## 6. 新代理接手的最小信息结构（概念级）

【推测】最小必要集是"可分层拉动的洋葱"，而非全量记忆：

1. **锚点层**：哪个工程、目标宪章（含价值判据与非目标）、当前阶段。缺此层一切皆噪音。
2. **态势层**：任务图状态机快照（已过/在途/因何阻塞）＋关键决策记录（含被否备选及理由）。
3. **行动层**：当前可认领的任务契约，每份自足（目标、输入指针、验收标准、约束、影响面）。
4. **教训层**：与该任务区域相关的沉淀规则切片——是切片，不是全库。
5. **溯源层**：验收记录、错误条目、进化日志的指针，供必要时下钻。

【确定】由约束 2/3 推出：1–3 层构成"接手内核"，必须**仅凭工作区可重建**。另两条横切要求：教训与决策带**置信标注**（已验证规则 vs 假设），否则新 agent 把传说当法律；条目带**时效/作废标记**，否则内核随工程膨胀而失最小性。最小结构服务"继续干活"，深理解按需沿指针扩展。

## 7. 关键取舍与开放问题

**取舍**：①严格度 vs 成本——仪式要花钱，须按任务风险分级配置；②解耦 vs 一致性——隔离越多集成风险越大，共享状态需一致性规则兜底；③沉淀 vs 噪音——全量沉淀写着便宜用着贵，策展成本与稀有教训流失之间要定价；④技能化 vs 僵化——技能降方差但抗变化，过早固化会把事故冻成法律；⑤集中主控 vs 层级扩展——单主控保一致性但成瓶颈；⑥记忆分层 vs 知识边界天然模糊。

**开放问题**：【存疑】以下各项在本阶段无法判定，仅可列出——验收标准的出处独立性如何实现（谁写标准才能避开规划盲点）？委托人不完全知道目标时讨论的收敛判据是什么？进化环自身的收敛判据——凭什么说系统在变好而非在堆积？价值验收由谁何时执行？沉淀物的淘汰/降级（记忆衰减）如何设计？对抗性工件在模型内还是外？验收效果天然滞后的任务（集成后果事后显现）如何立约？

## 8. 最值得优先解决的三个概念性问题

【推测，按"若错则连坐范围"排序】

1. **验收标准的可信度**（Goodhart＋盲点继承）：验收、错误收集、进化都以标准为锚；标准错则全环优化错误目标。它位于质量因果链最上游。
2. **归因与进化环的质量控制**：本构想区别于普通工作流的唯一卖点是进化环；进化若传播迷信则不如不进化。且有自指结构——谁给门禁设门禁。
3. **工作区的一致性语义**（可见性、可变性、失效规则）：约束 2/3/4 全压在"工作区是可靠黑板"这一假设上，伪解耦最集中于此，接手内核的可重建性也由它决定。【存疑】该语义能否在概念层既轻量又可靠地成立（既防半成品污染、又不把工作区管成数据库），尚不可判。

## 9. 对主控整合者的建议（10 条）

1. 把价值验收与合规验收显式分层，别让逐条验收冒充终点。
2. 先定义工作区状态语义（可见性、可变性、失效），它是全部约束的地基，不是实现细节。
3. 给进化环加自质量门：归因→规则晋升须独立复核，并设"归因不明→观察"类别以防强行归因。
4. 技能与记忆划界（程序性/声明性），同一事实单一出处，禁止双重记账。
5. 验收标准设出处独立性要求，高风险条目至少经非规划者视角复核。
6. 接手按"分层拉动"设计：内核最小、指针扩展，强制内核可仅凭工作区重建。
7. 引入按风险分级的严格度刻度，防工作流沦为官僚仪式。
8. 显式建模变更管理：目标/方案变更如何使在途任务失效与重订约。
9. 先定义"系统在变好"的收敛判据与度量，再让进化环转起来。
10. 列出人类不可自封的闸门清单：目标批准、高风险动作、价值验收、L0 晋升。
