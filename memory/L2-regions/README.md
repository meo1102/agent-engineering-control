# L2 区域记忆

按工程区域切分，高频、局部、易变。每个区域有自己的负责人；区域记忆默认**不跨项目**，需要跨项目时走晋升。

## 区域划分

| 区域 | 记什么 | 典型条目 |
| --- | --- | --- |
| dev（开发） | 实现约定、代码地图、环境坑、常见缺陷 | "改 X 之前必须先做 Y" |
| acceptance（验收） | 判例、边界案例、常见误判 | "这类输出要看边界值而非平均值" |
| convergence（收敛） | 收敛判据、遗留问题模式、发布记录 | "哪些遗留可接受、哪些必须清零" |
| collaboration（协作） | 派发经验、上下文包模板、执行者画像 | "哪类任务适合哪种执行者" |

## 条目模板

```markdown
## R-<区域>-000 标题
- 观察（发生了什么）：
- 判断（我们怎么理解）：
- 适用范围：
- 反例 / 不适用：
- 置信度：高 / 中 / 低
- 来源：任务 / 验收 / 复盘
- 复审日期：
- 所有者：
- 状态：active / promoted / archived
```

## 晋升规则

- 同区域同模式复现 ≥2 次 → 可提交 L1 晋升候选；
- 跨 ≥2 项目复现 → 可提交 L0 候选；
- 晋升后原条目保留并标记 `promoted`，不删除。

## 各区域示范条目

### dev

- 观察：任务卡没有写明"允许修改哪些文件"时，执行者倾向于扩大改动范围。
- 判断：输出契约必须包含"改动边界"。
- 适用范围：涉及既有代码库的任务。
- 置信度：中。

### acceptance

- 观察：仅检查"功能是否存在"的验收，漏掉了"边界条件是否正确"。
- 判断：验收标准至少要覆盖正常路径 + 一个边界 + 一个失败路径。
- 适用范围：所有功能性交付。
- 置信度：中。

### convergence

- 观察：遗留问题没有指定"接受人"时，收敛会被无限推迟。
- 判断：每条遗留必须绑定接受人与回看日期，否则不得收敛。
- 适用范围：所有项目收敛。
- 置信度：高。

### collaboration

- 观察：上下文包给得越全，执行者越容易忽略其中真正的约束。
- 判断：上下文包应按"约束 > 判例 > 背景"排序，约束置顶。
- 适用范围：任务派发。
- 置信度：低（待验证）。
