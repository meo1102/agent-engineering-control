# 六个协调接口

> 每个接口都回答：谁给谁、给什么、最小字段、硬规则、失败模式。

## I1 方向与边界（人类 → 集群）

**目的**：把“为什么做、什么不能牺牲、什么算失败、什么情况停”变成可执行边界。

**最小字段**：

- 目的、受益者、成本承担者、价值排序；
- 成功定义、失败定义（至少一个反例）；
- 非目标；
- S1–S4 风险分级与升级触发；
- 预算与停止条件；
- 边界变更权（谁有权改）；
- 施工蓝图（工作包/接口/未知/阶段验收；集群起草，人类批准）。

**硬规则**：

- 没有失败定义，目标不可证伪；
- 没有非目标，范围会蔓延；
- 没有具名所有者，不发布、不声称可用；
- **蓝图未批准，不 freeze**；
- **开放 S1/S2 未清零，不 freeze**；
- **没有 freeze，不 start；没有 start，不执行**；
- **freeze/start 只授权一个阶段，不是整个项目**；
- 阶段结束必须停，不能自动续跑；
- 变更不得原地改冻结基线。

**输出不是一个文件，而是一个包**：

1. `human/direction.md`（人类确认的宪章版本）；
2. `BLUEPRINT.md`（人类批准的本阶段施工蓝图）；
3. `human/decisions.md`（含被否决选项与理由）；
4. `ledger.md`（开放 S1/S2=0；S3/S4 有主/有期限）；
5. `gates/<date>-charter-freeze.md`（阶段/范围/预算/停止/验收）；
6. `gates/<date>-start-order.md`（开工令：下达人/首次报告点/暂停权）；
7. `STATUS.md` 的阶段授权段与开工令段。

**接收者**：集群管家是保管/路由者，不是解释者；实现 agent 接阶段授权包；新 agent 接手必须拿完整包，不能只拿 `direction.md`。

**失败模式**：方向写成口号；人类只给目标不给边界；集群把假设当授权；把宪章当“整个项目开工令”；蓝图写成完整设计文档而迅速过期；freeze 被读成自动开工。

## I2 决策包（集群 → 人类）

**目的**：让人类只做“不可替代的判断”，不被流水账淹没。

**最小字段**：

- 要决定什么（一个可裁决问题）；
- 选项与代价（至少包含“不做”“更差但更便宜”“集群不建议”的选项）；
- 证据（E1/E2/E3，链接）；
- 异议（开放 S1/S2、少数意见）；
- 建议与不确定性；
- 期限与不决定的默认（暂停/缩小，不是通过）。

**硬规则**：

- 摘要必须声明删了什么；
- 人类可绕过摘要直读原始对象；
- 没有“反选项”的决策包不是选择，是提案包装；
- 变更请求复用本接口：必须写影响（范围/返工/预算/验收/风险）和“接受/拒绝/挂起”三个选项；
- 不接受“默认通过”；超时默认暂停/缩小。

**失败模式**：主 agent 控制选项与措辞；人类只看推荐；超时默认通过；把 blueprint/charter 级变更当 task 级静默处理。

## I3 写入与证据（集群 ↔ 工作区）

**目的**：让产物/证据/事实有身份、版本、状态，候选不污染生产。

**最小字段**：

- 产物：路径、版本、作者、状态（草稿/候选/已验收）、证据链接；
- 事实：ID、陈述、来源、方法、时间、状态（已捕获/已核验/有争议）、核验人；
- 异议：ID、级别、类型、主张、证据、处理人、状态、裁决。

**硬规则**：

- 候选不得当已验收事实；
- 模型输出默认是“主张”，不是事实；
- 高影响事实由非作者核验；
- 记录不可静默改写；更正追加。

**失败模式**：半成品被下游消费；旧证据覆盖新对象；自引用当独立证据。

---

## I4 原始现场（工作区 → 人类）

**目的**：让人类“看现场”，而不是看集群加工的叙事。

**最小字段**：

- `STATUS.md`（当前状态）；
- `ledger.md`（异议/事实）；
- 原始证据（日志/测试/截图/复现步骤）；
- 开放 S1/S2 与阻断项；
- 文档时效（哪些是当前/历史）。

**硬规则**：

- 人类可绕过摘要直读；
- 摘要必须声明删了什么；
- 没有 E1/E2 的“通过”不算通过。

**失败模式**：人类只读摘要；工作区自述冒充现场；旧文档当当前状态。

---

## I5 验收与落地（人类 → 工作区）

**目的**：把“真实使用/遗留/照护/退役”变成人类可追溯的接受。

**最小字段**：

- 项、版本、情境、使用者；
- 决策（接受/有条件接受/拒绝）；
- 证据（E1/E2）；
- 剩余风险与接受者；
- 照护者、成本、退役路径。

**硬规则**：

- 没有具名照护者，不算落地；
- 人类接受的是“特定版本、特定范围、特定遗留”；
- 外部性需要受影响方/合法权威参与。

**失败模式**：验收通过即宣布落地；文件齐全冒充可运维；无人接受遗留。

---

## I6 交接与验证（集群 ↔ 集群）

**目的**：让另一个上下文能接住，而不是重新发明。

**最小字段**：

- 任务/产物、输入版本、验收判据；
- 证据、未决问题、否决记录；
- 验证记录（谁、用什么方法、结果）；
- 下一步与责任。

**硬规则**：

- 验证者只读产物/证据，不读实现者推理；
- 不共享未验证前提；
- 高影响验收必须非作者。

**失败模式**：验证者被实现者摘要同化；交接只给结论不给否决；多 agent 共享同一污染上下文。
