# 角色：功能，不是人头

## 1. 默认单 agent + 人类

原型默认不要求多 agent。一个 agent 可以兼任实现、测试、记录；人类做方向、S1/S2、最终验收、抽样。

| 角色 | 默认由谁 | 职责 | 不做什么 |
|---|---|---|---|
| **人类方向所有者** | 人类（具名） | 方向/非目标/失败定义/S1–S4/预算/停止；蓝图批准；S1/S2 裁决；开工/暂停；最终验收/遗留接受；抽样 | 常规分诊、逐条核事实、每门签字、替集群写蓝图 |
| **集群管家** | 一个 agent | 起草蓝图、路由、任务板、变更分诊、S3/S4、升级、STATUS 维护 | 独自裁决 S1/S2；删除/改写异议；替人类下开工令；替人类接受遗留 |
| **实现者** | 一个 agent | 按冻结蓝图实现、测试、事实记录、自验、申报偏差 | 给自己发验收结论；改蓝图/验收判据；接蓝图外任务 |
| **验证者（可选/轮值）** | 另一个上下文/红队 | 高影响事实复核、S1 调查、异议挑战 | 读实现者推理；与被审方共享目标/奖励 |
| **工作区策展** | agent/人 | STATUS、台账、证据、时效、SUPERSEDED | 改写记录；泄露匿名来源 |

### 1.1 宪章/蓝图/阶段授权不是普通任务

- **宪章**由人类与 agent 共写，人类确认；集群管家只做保管/路由，不做解释或扩权。
- **施工蓝图**由集群起草、人类批准；它回答“怎么做”，不回答“为什么/什么不能牺牲”；一页为限，按阶段版本化。
- **实现 agent** 接的是**阶段授权包**（宪章版本 + 已批准蓝图 + freeze 门禁 + start 开工令 + 任务板 + 异议状态 + 验收判据），不是“拿到 direction.md 就开做”。
- **新 agent 单独接手**必须拿完整包：宪章、蓝图、决策记录（含否决）、异议状态、阶段授权、开工令、STATUS、证据。
- **没有 freeze，不 start；没有 start，不执行；阶段结束，必须停。** 阶段授权只覆盖一个阶段，不覆盖整个项目。
- **变更**：task 级管家处理；blueprint/charter 级必须人类裁决；不原地改冻结基线。

## 3. 单 agent 的角色切换规则

单 agent 可以兼任，但必须显式切换并留下记录：

1. **实现时**：只读任务与必要上下文，写代码/测试/事实；不写“验收通过”。
2. **自验时**：只回答“做完了吗、证据可复现吗、偏差报了吗”；不给自己发“独立通过”。
3. **验证时**（如果同一个 agent 无第二上下文）：改用**外部检查**——人类真机、独立工具、另一个项目的 agent；至少不能只读自己刚写的摘要。
4. **验收时**：人类做；agent 只整理证据与选项。

**硬规则**：高影响验收至少有一次非作者检查；没有就写“未独立验证”，不能写“通过”。

## 4. 验证者的上下文隔离

- 只读：任务、产物、证据、原始日志、判据。
- 不读：实现者的推理、聊天摘要、自评。
- 不共享：同一目标、同一奖励、同一未验证前提。
- 输出：验证记录（方法、结果、异议），不是“我同意”。

## 5. 人类注意力合同

| 人类做 | 人类不做 |
|---|---|
| 定方向/目标/非目标/红线/预算/停止 | 常规异议分诊 |
| 批准施工蓝图、freeze/start | 替集群写蓝图/做任务分解 |
| S1/S2、不可逆、重大外部性、价值冲突 | 逐条核事实 |
| 最终验收/落地接受 | 每道门签字 |
| 每周抽样 1–2 条 S3/S4 | 维护台账/角色行政、逐条批 task 变更 |

**预算**：常规事务 ≤2 小时/周（可调）；S1/S2 另计。超预算先缩范围/授权，不加控制。

## 6. 反模式

- 为了“可问责”新增四个常设角色；
- 让人类参加每道门；
- 让实现者兼任唯一验证者；
- 让验证者读实现者摘要；
- 让管家同时控制叙事与证据；
- 把“集群”当默认，实际只是角色切换；
- 把蓝图写成完整设计文档，或让 agent 自己批准蓝图；
- 把 freeze 当开工令，或把 start 当整个项目授权；
- 每次新需求直接口头加活，不判断 task/blueprint/charter。
