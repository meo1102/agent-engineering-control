# 架构：三个域、六个接口、一个状态页

## 1. 为什么是三个域

AECW 原型不是“多 agent 框架”，而是一个**责任结构**。三个域分别回答三个不可互相替代的问题：

| 域 | 核心问题 | 失败方式 | 不能用什么补偿 |
|---|---|---|---|
| **人类** | 为什么做、什么不能牺牲、什么算失败、是否接受 | 要错了 | 更多 agent、更多文档 |
| **集群** | 怎么做、怎么学、怎么验证 | 做偏了/学歪了 | 更多人类签字 |
| **工作区** | 现在真实存在什么、证据在哪、怎么交接 | 看不见真相 | 更多摘要/仪表盘 |

## 2. 结构图

```text
┌────────────────────────────────────────────────────────────┐
│ 人类域 human/                                              │
│  direction.md（方向/边界/S1–S4/预算/停止）                  │
│  decisions.md（人类决策）  acceptance.md（真实使用/落地）   │
└───────────────▲──────────────────────────┬─────────────────┘
                │ I2 决策包                 │ I1 方向/边界
                │ I4 原始现场               │ I5 验收/落地
┌───────────────┴──────────────────────────▼─────────────────┐
│ 集群域 cluster/                                            │
│  roster.md（角色） board.md（任务） runs.md（运行）          │
│  learning.md（观察/教训/候选）                              │
└───────────────▲──────────────────────────┬─────────────────┘
                │ I6 交接/验证              │ I3 写入/证据
┌───────────────┴──────────────────────────▼─────────────────┐
│ 工作区域 workspace/ + STATUS.md + BLUEPRINT.md + ledger.md + gates/ │
│  work/（产物） evidence/（E1） memory/（记忆） landing/（落地）│
└────────────────────────────────────────────────────────────┘
```

## 3. 六个接口

| # | 接口 | 方向 | 一句话规则 |
|---|---|---|---|
| I1 | 方向与边界 | 人类 → 集群 | 没有边界，就没有“默认相信” |
| I2 | 决策包 | 集群 → 人类 | 只给人类不可替代的判断，不给流水账 |
| I3 | 写入与证据 | 集群 ↔ 工作区 | 候选不得当已验收事实 |
| I4 | 原始现场 | 工作区 → 人类 | 人类可绕过摘要直读 |
| I5 | 验收与落地 | 人类 → 工作区 | 没有具名照护者不算落地 |
| I6 | 交接与验证 | 集群 ↔ 集群 | 验证者只读产物/证据，不读推理 |

## 3.5 宪章/蓝图交接与阶段冻结

**宪章不是“交给某个 agent 执行”的任务，而是人类与集群共写的共享基线。** 输出不是 `direction.md` 一个文件，而是“宪章 + 已批准蓝图 + 异议状态 + 阶段基线 + 开工令”的包。

```text
人类 + agent 共写 direction
  → 集群起草 BLUEPRINT；人类修改并批准（工作包/接口/未知/验收）
  → 异议窗口：开放 S1/S2 必须清零；S3/S4 有主/有期限
  → freeze：人类确认宪章与蓝图；写 charter-freeze 门禁
  → start：人类下达开工令；写 start-order
  → 集群执行；阶段结束停、报告、等下一道门
```

**谁接**：

- 集群管家是宪章/蓝图的保管/路由者，不是解释者；不能“拿到文件就开做”。
- 实现 agent 接的是**阶段授权包**：宪章版本 + 已批准蓝图 + freeze 门禁 + start 开工令 + 任务板 + 开放/已关闭异议 + 验收判据。
- 新 agent 单独接手时，必须同时拿到宪章、蓝图、决策记录（含否决）、异议状态、阶段授权、开工令、STATUS、证据；只给宪章等于让它重新解释。
- 人类保留：宪章批准、蓝图批准、S1/S2、开工/暂停、阶段继续/收缩/停止、最终验收。

**硬规则**：

- 蓝图未批准 → 不 freeze；
- 开放 S1/S2 未清零 → 不 freeze；
- 没有 freeze → 不 start；
- 没有 start → 不执行；
- start 只授权一个阶段，不是整个项目；
- 阶段结束必须停，不能自动续跑；
- 新增范围要重新 freeze/start。

CLI：

```powershell
node bin/aecw.mjs blueprint <dir> --stage grow-1
node bin/aecw.mjs freeze <dir> --charter-confirmed --stage grow-1 --scope ... --budget ... --stop ... --acceptance ...
node bin/aecw.mjs start <dir> --by <人类> --first-report <报告点>
```

## 3.6 蓝图、开工令与变更

**蓝图回答“怎么做”，开工令回答“现在开始”。** freeze 是基线锁定，不是自动开工；start 是人类的显式 go。

**蓝图最小内容**：本阶段目标/非目标、工作包（输出+验收+依赖）、接口契约、未知/假设、本阶段不做、阶段验收、变更记录。一页为限，按阶段版本化；集群起草，人类批准。

**变更分三级**：

| 级别 | 例子 | 谁决定 | 处理 | 重新 freeze/start |
|---|---|---|---|---|
| task | 同一工作包内换实现/补测试 | 集群管家 | 记 board/runs；不改验收 | 否 |
| blueprint | 加/删工作包、改接口/验收/顺序/依赖 | 人类 | CR + 影响分析 + 新蓝图版本 | 是 |
| charter | 改目的/非目标/失败定义/S1–S4/预算 | 人类 | 先停；重谈宪章；新 freeze | 是 |

**当前阶段怎么办**：默认“做完再切”（当前工作包接近完成且不被新需求作废）；否则“检查点停车”（保存证据、停、重规划）或“中止”（进 compost/重立项目）。

**硬规则**：

- 不原地修改冻结基线：v1 保留，v2 写 diff + 理由 + 批准人；
- 变更不得静默改验收判据；改了就重新 freeze/start；
- 每阶段设变更预算（例如最多 2 次 blueprint 级变更）；超了停、重规划；
- 人类可随时叫停；影响分析在停之后做；
- 集群不能裁决 charter 级变更；技术发现也走 CR。

CLI：`node bin/aecw.mjs change <dir> --type task|blueprint|charter --title ...`；裁决用 `--id CR-001 --decision 接受|拒绝|挂起`。开放 blueprint/charter 变更时 `check` 给 WARN。

## 4. 状态模型

- **STATUS.md**：唯一当前状态；包含阶段/阶段状态（seed/frozen/executing/paused/closed）、证据等级、已接受遗留、未测项、文档时效、下一步；第 7 节冻结、第 8 节开工令。
- **BLUEPRINT.md**：施工蓝图；版本、状态（draft/approved）、批准人、工作包、接口、未知、本阶段不做、阶段验收、变更记录。
- **ledger.md**：异议/事实/变更的流水；S1/S2 进 `inbox/`；S3/S4 一行；CR 详情进 `inbox/CR-xxx.md`。
- **gates/**：每道门一页；`charter-freeze` 锁基线，`start-order` 是开工令；有开放 S1/S2 时高风险动作暂停。
- **human/acceptance.md**：人类对真实使用/遗留/落地的接受。
- 旧文档标 `SUPERSEDED`；STATUS 冲突时以 STATUS 为准。

## 5. 权威矩阵

| 决定 | 人类 | 集群管家 | 实现者 | 验证者 | 工作区策展 |
|---|---|---|---|---|---|
| 方向/非目标/失败定义 | **决定** | 提议 | 知情 | 挑战 | 记录 |
| 施工蓝图 | **批准** | **起草** | 参与 | 挑战 | 版本化 |
| 阶段冻结/开工令 | **决定** | 记录 | 知情 | 知情 | 存档 |
| 变更裁决（blueprint/charter） | **决定** | 影响分析/提议 | 提出 | 挑战 | 记录 |
| S1/S2 裁决 | **决定** | 升级 | 提出 | 调查 | 存档 |
| S3/S4 裁决 | 抽样 | **决定** | 提出 | 可选 | 记录 |
| 任务分解/实现路线 | 例外 | **决定** | 执行 | 评审 | 承载 |
| 高影响事实核验 | 裁决争议 | 组织 | 记录 | **复核** | 存档 |
| 真实使用/落地接受 | **决定** | 组织 | 提供证据 | 审计 | 保存 |
| 元规则/权限/门禁 | **决定** | 提案 | 不碰 | 异议 | 版本化 |
| 紧急停止 | **可叫停** | **可叫停** | **可叫停** | **可叫停** | 记录 |

## 6. 默认形态：单 agent + 人类

原型默认**不**要求多 agent。一个 agent 可以兼任实现、测试、记录；但：

- 高影响验收要有一次**非作者**检查（人类真机/另一个 agent/独立工具）；
- 验证者必须用**新鲜上下文**，只读产物/证据，不读实现者推理；
- 需要独立调查时临时指定，不设常设“异议守护者”。

多 agent 是**可选放大**，不是原型的前提；没有上下文隔离的多 agent 只是“多个分叉的放大器”。

## 7. 原型边界

已实现的是**结构、工件、接口、CLI**；未实现的是 agent 运行时、模型路由、自动探针、截图、UI、数据库。原型先用文件系统跑通“谁在什么时候看什么、凭什么通过”，再谈自动化。

## 8. v0.9 部署架构：两个根、一个清单、一个状态源

> 依据：真实项目 `task-complete-toast-aecw` 的 `check`/`probe` 全绿，但 `STATUS`/README/board/decisions 仍互相矛盾。详见 [`PLAN-v0.9`](../../PLAN-v0.9-真实项目校准.md) 与 [`REVIEW`](../../REVIEW-task-complete-toast-aecw-2026-11-05.md)。

**两个根**：

```text
<repo>/
├─ package.json / index.js / client.js / lib/ / locale/ / test/  # 产品根（可在仓库根或 product/）
├─ aecw/           # 治理（STATUS/state/criteria/human/cluster/workspace/gates/inbox）
├─ PROJECT.json    # 项目清单：roots.product 定义产品根、安装目标、命令、工具版本
├─ README.md       # 只指路/产品说明
└─ AGENTS.md       # 只指路
```

**两个根 = 产品根 + 治理根，不强制产品根叫 `product/`。** `roots.product` 可以是 `.`（产品在仓库根）或 `product/`；`roots.governance` 指向 `aecw/`。`workspace/` 只放证据/记忆/落地，不放产品代码；根 README/AGENTS 不是第二份状态。

**一个状态源**：`aecw/state.json` 存阶段/发布/进化/采纳/证据债/布局/安装/远程；`STATUS.md` 是视图；其他文档只引用。  
**一个矩阵**：`aecw/criteria.md` 每条判据一行（`met/waived/deferred/failed` + 证据 + 人类裁决）；门禁是矩阵的视图。  
**四条泳道**：stage / maintenance / evolution / release；阶段关闭只关闭 stage，不关闭项目。  
**两层检查**：`check` 查文件/状态/判据/路径/命令/Markdown 围栏/文档状态；`probe` 查安装/路由/slot；两者都不能替代人类 E2。  
**动作完成 = 状态写回**：布局/安装/版本/tag/发布/远程变化后，先写 `state.json` + `STATUS` + 证据，再回复；`check` 校验 `state.layout`/`state.install`/`state.remote` 与 `PROJECT.json`、git origin 一致。

**最小落地顺序**：真话修复 → `PROJECT.json` → `criteria.md` → `state.json` → 升级 `check` → 再开下一阶段。  
**不做什么**：不新增四个常设角色；不要求所有文档自动生成；不把 `state.json` 做成数据库；不把 E2 写成 E1。
