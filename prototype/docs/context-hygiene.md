# 上下文卫生：不要让 agent 的“记忆”代替现场

> 来源：task-complete-toast 试点与两次状态五问接手测试。原型把以下规则做进结构，而不是靠提醒。

## 1. 三个等级

| 等级 | 含义 | 例子 | 能否当“通过” |
|---|---|---|---|
| **E1** | 运行事实，可复现 | 测试输出、日志、哈希、安装/路由探针 | 可以，带范围 |
| **E2** | 人类目视，无截图 | “我看到卡片出现/按钮可点” | 只能支持有限结论；无截图=证据缺口 |
| **E3** | 文档主张，未复核 | README 说“已安装”、历史 142/142 | 不能单独当证据 |

## 2. 十条规则

1. **运行态事实优先**：接手/门禁第一条事实是安装、加载、入口、路由、版本；文档只是主张。
2. **STATUS 单一当前状态**：其他文档是证据/历史；冲突以 STATUS 为准。
3. **旧文档标 SUPERSEDED**：同一事实多个时间切片时，当前只留一处。
4. **不引用行号**：行号会因插入文件头偏移；用节号/文本锚点。
5. **模型输出是主张**：高影响主张必须外部核验；自产自引不算独立证据。
6. **测试替身按真实签名**：桩比真实宽松，真机才暴露；包装/注入层单独测。
7. **编码显式 UTF-8**：写回断言无 `U+FFFD`；不用 PowerShell 默认编码改中文文件。
8. **高影响事实非作者核验**：作者=验证者时，只能写“可复现”，不能写“独立通过”。
9. **证据默认截图/录屏**：真机验收至少一张关键图；没有就写“证据缺口”。
10. **新 agent 接手测试**：只读 STATUS + 证据，回答五问；追问/分叉=上下文缺口。

## 3. 接手五问

1. 现在是什么状态？
2. 什么已验证（E1/E2/E3）？
3. 什么未测/被接受？
4. 下一步做什么？
5. 哪些结论不能信？

**指标**：追问数、分叉数、误读旧文档次数、需作者解释的地方。目标：0 分叉、0 追问、0 误读。

## 4. 上下文卫生检查单

- [ ] 有 STATUS.md，且 14 天内更新
- [ ] 人类所有者具名
- [ ] BLUEPRINT.md 已批准，且与 STATUS 阶段一致
- [ ] freeze/start 门禁与 STATUS 阶段状态一致
- [ ] 旧文档有 SUPERSEDED
- [ ] 没有“line 24”式行号引用
- [ ] 高影响事实有非作者核验
- [ ] 测试替身按真实签名
- [ ] 真机证据有截图/录屏，或写明缺口
- [ ] 没有把模型输出直接当事实
- [ ] 新 agent 能只读 STATUS + 证据回答五问
- [ ] 开放 S1/S2 为 0，或有书面接受

## 5. 反模式

- 用“文档说已安装”代替运行态探针；
- 用“160/160”代替“真机可用”；
- 用“多份文档都这么说”代替独立证据；
- 用“我们已经讨论过”代替记录；
- 用“集群”代替上下文隔离；
- 用“全绿”代替失败/未测清单。
